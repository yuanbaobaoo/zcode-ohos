# 01 构建与打包（macOS 主构建环境）

主构建环境为 macOS（真机经 hdc 连接安装调试）。鸿蒙本机构建时代的流程已废弃。

## 环境要求（`pnpm bundle:desktop -- --os ohos`）

### 必需（缺失时打包前置检查会明确报错）

| 项 | 要求与说明 |
|---|---|
| 构建机 | macOS（全流程仅在此验证；脚本是纯 Node，Linux 理论可跑但未验证） |
| Node / pnpm | 与仓库标准一致：Node 24.14、pnpm 10.33.2（以 `mise.toml` 为准） |
| OHOS command-line-tools | 含 hvigor / ohpm（hdc 仅装机需要）。hvigorw 按以下顺序解析：① `OHOS_HVIGORW`（可执行文件完整路径）② `OHOS_COMMAND_LINE_TOOLS` 或 `DEVECO_SDK_HOME`（SDK 根目录，取其 `bin/hvigorw`）③ 已知安装位置（当前含作者机器路径，**其他机器必须设置 ① 或 ②**） |
| libelectron.so | 167MB 不入库（超 GitHub 单文件限制）。**构建时自动从镜像下载并校验**（见下方"新环境一次性初始化"），`ZCODE_OHOS_ELECTRON_URL` 可指向自备镜像 |
| 网络可达 npm 源 | `pnpm install` 需要；hvigor 首次可能拉取 ohpm 依赖 |

### 可选（影响产出范围）

| 项 | 没有时的行为 |
|---|---|
| devecocli 签名材料 | 缺失时只产出未签名版（`-unsigned.hap`）。`build-profile.json5` 不入库（含签名材料路径/密码），缺失时自动从模板复制，空签名配置已实测可正常构建（hvigor SignHap 自动跳过） |

### 仅特定场景需要（日常打包不需要）

| 项 | 场景 |
|---|---|
| OHOS SDK clang + sqlite amalgamation（`~/sqlite-src/`，3530400） | 仅修改 `ohos/native/zcode-sqlite/zcode_sqlite.c` 后跑 `build.sh` 重编绑定时；日常打包直接使用仓库内预构建 `.node` |
| hdc + 真机 | 装机与调试（`hdc install` / `aa start` / hilog），打包本身不需要 |
| deveco cli（devecocli） | 仅签名初始化（`auth login` + `signature generate`）与系统层 UI 自动化（`devecocli ui`） |

## 新环境一次性初始化

1. `libelectron.so`（167,799,608 字节，sha256 `6cd73b11…844a`）不入库（超 GitHub 单文件限制）。
   **正常情况下无需人工处理**：缺失时构建脚本自动执行
   `ohos/scripts/fetch-libelectron.mjs`（默认从本仓库 GitHub Release 镜像下载并校验
   sha256：`releases/download/v3.14.3/libelectron.so`，升级 libelectron 时随版本
   tag 更新；`ZCODE_OHOS_ELECTRON_URL` 可覆盖为任意 http(s)/file 镜像；
   `ZCODE_OHOS_ELECTRON_AUTOFETCH=0` 关闭自动获取改为纯报错）。
   供应通道优先级：① GitHub Release 镜像（公开、永久、已实测可达且哈希一致）
   ② `ZCODE_OHOS_ELECTRON_URL` 自备镜像（内网/离线场景用 file:// 或自建 URL）
   ③ 终极兜底：从 [openharmony-sig/electron](https://gitcode.com/openharmony-sig/electron)
   源码构建（Chromium 132 / Node 20.18.1；该镜像仅源码无预编译产物，重量级构建，
   仅在所有镜像不可用时）。
   **镜像内容更新（如 libelectron 升级）时必须同步更新 fetch 脚本内的
   EXPECTED_SHA256 与 DEFAULT_URL。**
2. sqlite amalgamation 3530400 自 sqlite.org 下载到 `~/sqlite-src/`；
   `sh ohos/native/zcode-sqlite/build.sh` 自动探测 SDK clang 交叉编译。
3. 签名：`cd ohos && devecocli auth login`（浏览器华为账号，一次性）→
   `devecocli signature generate`（自动申请含受限 ACL 权限的 debug 证书并写入
   build-profile.json5）。本机既有绑定其他 bundleName 的签名材料不能复用。
   **开源项目定位：全流程本地 debug 签名，不做正式签名。**
   `ohos/build-profile.json5` 含签名材料路径与密码（机器相关、敏感），**不入库**：
   仓库提供 `build-profile.template.json5` 模板，`bundle-ohos.mjs` 检测到缺失时
   自动复制（空签名配置，实测 hvigor SignHap 自动跳过、正常产出未签名 HAP）；
   想要签名版再执行上面的 devecocli 命令写入真实配置。
4. 构建脚本已默认注入 `ZCODE_TARGET_OS=linux ZCODE_TARGET_ARCH=arm64`
   （agent bundle / bundled-tools 的落盘目标平台；宿主是 macOS 时必须）。

## 常用命令（仓库根目录）

**标准打包通道**（推荐发布用；产物按 `{productName}-{version}-ohos-arm64[-unsigned].hap`
命名落 `packages/desktop/dist/`，与桌面版同目录同规则）：

```sh
pnpm bundle:desktop:ohos                       # 等价 pnpm bundle:desktop -- --os ohos
pnpm bundle:desktop -- --os ohos --dry-run     # 只打印步骤
pnpm bundle:desktop -- --os ohos --skip-build  # 复用已有产物（内部仍会清 hvigor 缓存全量组装）
```

底层命令（开发迭代用，等价于标准通道拆步执行）：

```sh
pnpm install                                        # 依赖
sh ohos/native/zcode-sqlite/build.sh                # 交叉编译 zcode_sqlite.node
node scripts/build-ohos.mjs                         # 全量（workspace + desktop + agent + resfile 组装）
node scripts/build-ohos.mjs --skip-agent            # 迭代 main/host（agent bundle 不变时）
rm -rf ohos/.hvigor ohos/electron/build ohos/web_engine/build   # hvigor 增量不感知 resfile，装机迭代前必清
cd ohos && hvigorw assembleHap --mode module -p product=default -p buildMode=debug --no-daemon
hdc install -r ohos/electron/build/default/outputs/default/electron-default-signed.hap
hdc shell "aa start -a EntryAbility -b ai.ohpc.zcode"
hdc shell "hilog -z 40000" > dump.txt               # grep A00001/ai.ohpc.zcode
```

签名版产物依赖本机 debug 证书（仅本机/同 Profile 设备可装）；分发用未签名版
（`-unsigned.hap`），其他用户自行签名或源码构建。

构建流水线内容（`scripts/build-ohos.mjs`）：workspace 构建 → desktop 生产构建
（tsup + vite，**非零退出码 fail-fast，产物 out/ 不回滚，失败后勿装机**）→
agent bundle（zcode.cjs + 官方插件 + 技能包）→ resfile 组装（运行时
node_modules 闭包、随包 zsh、zcode_sqlite.node 双份落位、glm agent、搜索工具）→
libelectron io_uring 补丁（幂等，见约束文档）。

## 本地回归（macOS 直编验证适配层）

```sh
# darwin 版绑定 + 兼容层全套语义（数组/对象/宽参数/Smi 安全通道）
clang -shared -fPIC -O2 -undefined dynamic_lookup -DNAPI_VERSION=8 \
  -DSQLITE_ENABLE_COLUMN_METADATA=1 -DSQLITE_THREADSAFE=1 -DSQLITE_DEFAULT_journal_mode=1 \
  -I"$(node -p 'require("path").dirname(process.execPath) + "/../include/node"'')" \
  -I ohos/native/zcode-sqlite \
  ohos/native/zcode-sqlite/zcode_sqlite.c ohos/native/zcode-sqlite/sqlite3.c \
  -o /tmp/zcode_sqlite_darwin.node
ZCODE_SQLITE_TEST_MODULE=/tmp/zcode_sqlite_darwin.node node .ohos-test/nodeSqliteCompat.test.mjs
```

装机操作与冒烟清单见 [../BRINGUP.md](../BRINGUP.md)；真机 UI 自动化
（CDP 通道）见 `ohos/scripts/device-cdp.mjs` 头部注释。
