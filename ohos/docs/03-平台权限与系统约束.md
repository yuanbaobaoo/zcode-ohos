# 03 平台权限与系统约束（HarmonyOS）

本文是适配层依赖的**平台事实清单**：每一条约束都对应代码中的具体对策。
改动相关模块前先对照本文，破坏这些对策会导致崩溃或功能回退。

## 系统权限（ohos/electron/src/main/module.json5）

| 权限 | 类型 | 作用 | 缺失后果 |
|---|---|---|---|
| `ohos.permission.CUSTOM_SANDBOX` | system_grant + Profile ACL | 动态沙箱：允许子进程 **exec 用户目录 ELF**（harmonybrew 全套工具链 git/java/node 对 agent 与终端可用的前提） | 终端/agent 执行 brew 工具报 EPERM（toybox 错误文案与"未安装"相同，注意甄别） |
| `ohos.permission.kernel.ALLOW_WRITABLE_CODE_MEMORY` | 受限 ACL | 阻止 libadapter `ShouldDisableJit()` 向全部进程注入 `--js-flags=--jitless` | renderer 退回解释执行，`WebAssembly` 对象不存在（diffs.worker 连环报错） |
| `ohos.permission.READ_WRITE_USER_FILE` | 受限（user_grant） | 读取真实用户 home（`~/.zshrc`、`.harmonybrew` 等） | 用户 shell 环境注入与 brew 前缀探测失效 |
| `ohos.permission.ACCESS_USER_FULL_DISK` | manual_settings（PC/2in1，API 22+） | 全盘文件访问；**不弹系统授权框**，需应用自行引导用户到设置页开启 | 沙箱外文件不可读 |

权限申请流程（EntryAbility.ets）：`READ_WRITE_USER_FILE` 在启动时
`requestPermissionsFromUser` 申请；`ACCESS_USER_FULL_DISK` 因是 manual_settings 类，
必须先 `uiContext.showAlertDialog` 说明用途、用户确认后再
`atManager.requestPermissionOnSetting` 拉起系统面板（拒绝则引导跳转应用详情页）。
`system_grant + ACL` 类权限由 debug Profile 携带，`devecocli signature generate`
自动申请，无需用户操作。

## V8 / NAPI 约束（libelectron，Chromium 132 / Node 20.18.1）

### Smi 参数铁律（最重要）

libelectron 的 V8 为**间接 Local ABI**（`v8::Value::IsNumber` 首指令即
`ldr x8,[x0]` 解引用 this），而 `v8::Object::Get` 的 **Smi 快路径返回裸 tagged 值**
而非槽位地址。因此：

- **任何数字（Smi）经 `napi_get_element` / `napi_get_property` 进入 native 即 SEGV**
  （值形如 `0x12` = `9<<1`，被当槽位地址二次解引用）
- 安全通道：字符串/对象/BigInt（堆对象，慢路径返回槽位）、
  `napi_get_cb_info` 的位置参数（argv）
- 对策：`nodeSqliteCompat` 的 statement 包装层（`wrapStatementPositional`）把
  数组参数展开为位置参数、对象参数改写为位置参数；native 侧 argv 按实际 argc
  动态分配。**新增任何 NAPI 取值路径必须维持"数字只走 cb_info 通道"**

### JIT / WASM

- Node 侧进程（main/host/agent）：沙箱默认禁 RWX 映射，需在进程早期执行
  `prctl(PRCTL_SET_JITFORT)`——由加载随包 sqlite 绑定的模块初始化顺带完成
  （`loadNodeSqlite()` 即触发，各进程入口引导）
- Chromium 侧进程：依赖 `ALLOW_WRITABLE_CODE_MEMORY`（见权限表）
- 设备开启高级安全模式（AdvSecMode/dsmm）时无视权限强制 jitless，消费级设备
  未开启；命中时 WASM 退回不可用

## 内核 / 沙箱约束

| 约束 | 事实 | 对策 |
|---|---|---|
| io_uring 被 seccomp 拒 | syscall 425（`io_uring_setup`）触发 SIGSYS 击杀整进程；NodeService 由 appspawn 拉起**不继承 main env**，无法用 `UV_USE_IO_URING=0` 注入 | 构建期二进制补丁 `ohos/scripts/patch-libelectron-disable-io-uring.py`（内容定位、幂等，已挂进 build-ohos）：跳过 libuv iou 初始化 + `uv__node_patch_is_using_io_uring` 恒返 0 |
| ptmx 不可用 | `/dev/ptmx` 对应用域 SELinux 拒绝 → openpty/forkpty 均不可用（fork+exec 本身正常） | 终端走 main 进程中继：首选 node-pty（真 pty，平台开放后自动生效），失败降级 stdio 管道 + 应用层行级回显（无全屏交互的已知代价） |
| el1 bundle 二进制 noexec | HAP 安装区 ELF exec 报 Permission denied → 随包 zsh 等无法直接作为 shell 启动 | shell 回退 `/bin/sh`（toybox，系统 rootfs 可 exec）；zsh 可由用户经 harmonybrew 安装（动态沙箱下用户目录 ELF 可 exec） |
| `/storage/Users` 顶层不可枚举 | 顶层 readdir/glob 返回空（find 亦空），但**子目录直接访问正常** | harmonybrew 前缀解析**直接探测** `/storage/Users/currentUser/.harmonybrew`（标准 PC 路径），readdir 扫描仅作多用户形态补充（`services/ohos/ohosUserShellEnv.ts`） |
| appspawn env 隔离 | NodeService（host）不继承 main 进程 env（实测注入探测变量为 undefined） | 用户 shell 环境在 **main 与 host 双入口**各自重放（同一共享模块）；agent Worker 及其 Bash 子进程经 host env 继承 |
| 用户目录 ELF 默认禁 exec | debug_hap 域 MAC 拦截（与权限位无关） | `CUSTOM_SANDBOX`（见权限表）；开源项目全流程保持本地 debug 签名，无需正式签名 |

## 工具链行为

| 项 | 事实 | 对策 |
|---|---|---|
| hvigor strip | HAP `libs/arm64-v8a/` 内的 `.node`/`.so` 会被 `stripped_native_libs` 去符号（md5 与源构建不同是**正常现象**，代码一致） | 对账二进制时用行为验证或符号文件，不要按 md5 误判"旧产物" |
| hvigor 增量不感知 resfile/libs | 增量构建可能打包旧资源（"1 秒构建成功"多为缓存） | 迭代装机前 `rm -rf ohos/.hvigor ohos/electron/build ohos/web_engine/build` 全量重打 |
| `app.isPackaged` 恒 false | exec 名是 `electron`，Electron 打包判定失效 | 涉及打包态分支需 OHOS 显式守卫（勿信 isPackaged） |
| tsup 构建失败必须看全输出 | 构建产物 out/ 不因失败回滚，staging 会残留旧文件 | 流水线对非零退出码已 fail-fast；人工跑构建时确认无 error 再装机 |

## 已知限制（当前接受）

- **终端无全屏交互**：管道哑终端无 TIOCSCTTY，vim/top/htop 不可用；行级回显下
  mksh 输出偶有前导空格（纯视觉）。平台开放 ptmx 后 node-pty 首选路径自动接管
- **`brew` 命令本体不可用**：依赖 `/proc/self/exe` 定位自身，沙箱内指向上游
  不可达路径；brew 安装的工具（git/java/node…）不受影响
- **HNP 随包安装被 HarmonyOS 7 拒绝**（错误码 9568407）：恢复路径已在
  module.json5 注释留档；agent 当前以 host 进程内 Worker 运行（app-server 模式）
- **内置 Provider 配置远端刷新 HTTP 400**：服务端拒绝该形态请求；
  bundled 配置（`ZCODE_BUILTIN_PROVIDER_CONFIG_FILE` 指向 resfile 实际落盘位置）兜底生效
- **无项目即席对话不入任务列表**：与产品语义相关，待对齐（桌面版行为对照）
