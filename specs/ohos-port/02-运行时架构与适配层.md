# 02 运行时架构与适配层

本文描述运行时架构与平台适配：每条先给平台约束，再给当前实现。平台事实的根因见
[03](./03-平台权限与系统约束.md)。

## 进程模型

```
HAP（io.github.yuanbaobaoo.zcode）
 └─ main（Electron main，ArkTS EntryAbility 拉起）
     ├─ renderer / GPU（Chromium 子进程，XComponent 内 web 内容）
     └─ NodeService host（appspawn 拉起，不继承 main env）
         ├─ host 服务（会话/任务索引/存储）
         │   └─ agent CLI = 进程内 Worker（worker_threads 跑 zcode.cjs）
         └─ 终端会话池在 main（shell 由 main 域托管）
```

## 适配点

**agent 以 host 进程内 Worker 运行**：exec 链路受限，agent 不独立进程。stdio 管道模拟
ChildProcess；Worker `online` 事件映射为 spawn 事件，是 runtime lifecycle "available" 的
触发源（任务列表依赖，勿删）。

**agent Worker 的 stdout 是 JSON-RPC 协议专用通道，OHOS 适配代码严禁 `console.log`**：
日志混入协议管道会让宿主 JSON.parse 失败、protocol_parse_error 断链，并可能引发 agent
无限重生。OHOS 下任何会被 agent Worker 加载的模块（`@zcode/shared` 的 sqlite/compat 链路）
一律用 `console.error`/serviceLogger。诊断面：transport 异常关闭落 warn（带帧长度与哈希，
不落原始帧内容），worker stderr 实时落 serviceLogger（`packages/services/src/zcode-agent/`）。
OHOS 的 worker_threads `exit` 事件在 stdout 异常关闭场景可能不触发，进程回收不能只靠 exit。

**seccomp 拒 io_uring（syscall 425），任一进程首次异步文件 IO 即 SIGSYS**，且 host 由
appspawn 拉起不继承 env、无法用 `UV_USE_IO_URING=0` 注入。
→ 构建期对 libelectron.so 做 4 字节×2 二进制补丁禁用 io_uring（`ohos-patch-libelectron.mjs`，
按 `UV_USE_IO_URING` 字符串地址反查 adrp/add 引用对做动态锚定；幂等，纯 Node）。

**沙箱默认禁 RWX，V8 保留 CodeRange 会直接 OOM**。
→ 各进程入口早期 `loadNodeSqlite()` 触发 JIT 解锁：首选绑定 `zcode_sqlite.node` 模块初始化
自带 `prctl(0x6a6974, …)`（选项号 ASCII 即 "jit"）；兼容层在无 prctl 的绑定上额外加载
adapter 取解锁副作用。agent 经 host env 继承；Chromium 侧靠 `ALLOW_WRITABLE_CODE_MEMORY`
权限阻止 jitless 注入。

**HOME 对应用常无写权（首个 logger mkdir 即 EPERM）**。
→ main 最早引导做真实落文件的写权探测（mkdir 成功不代表可写）；可写则以真实 home 为数据根，
不可写先落应用沙箱保启动，首窗就绪后弹一次目录授权（ArkTS UriGrantHelper 持久化），
授权后迁回。

**GUI 应用继承不到用户 zsh 登录环境，agent 的非交互 spawn 不读 rc 文件，工具链不可见**。
→ `services/ohos/ohosUserShellEnv.ts` 在 main 与 host 双入口注入用户 shell 环境（appspawn
env 隔离），agent Worker、Bash 子进程与终端 shell 都从 host env 继承。用户环境只有
**登录 shell 快照 v3** 一个来源：不静态重放 rc、不探测或前置任何包管理器前缀（exec shim
只解决脚本执行，不提供 PATH，见 03）。首个 Host spawn 前等待快照落盘（有界 4s）。HiShell
与 HarmonyBrew 只是该 zsh 环境的常见来源，应用当普通用户配置处理，不识别、不特判。

**登录 shell 快照 v3：main 采集、落盘、host 合并**。
→ main 引导后异步跑 `/usr/bin/zsh -ilc 'env -0'`（与用户终端同一个 shell、同一套 rc；标记对
提取防 rc stdout 污染，12s 超时）。`cwd=<realHome>`（rc 里的工具链初始化要求 cwd 对进程 uid
可读）；显式最小基线 env（`HOME/PATH/LANG/TMPDIR/TERM=dumb`），不继承 `process.env`。结果
剔除 `_/SHLVL/PWD/OLDPWD/TERM` 与空值，落盘 `<realHome>/.zcode/v2/ohos-login-env.json`
（v3：`{version, capturedAt, shell, cwd, env}`）。
→ 应用：PATH 用快照整体替换（唯一来源）；其余键覆盖，`SHELL_EXPORT_SKIP_KEYS` 保护
HOME/XDG/TMPDIR 等应用管理键。无快照时保持引导自身 PATH，不重放 rc；main 在首个 Host spawn
前等待快照（`awaitRuntimeEnvReady`，4s 超时）。采集仅在 main：host 视图无 `/usr/bin/zsh`，
且 main 异步 spawn 不触发 clone3 SIGSYS。

**TMPDIR = `~/.zcode/tmp`；socket 目录单独走 el2**。
→ 平台 `/tmp` 属主 1076、`0770`，应用 uid 无写权。zcode 取 `<realHome>/.zcode/tmp`：与
`/storage/Users` 同一文件系统，临时文件 move 到工作区不会 `EXDEV`；启动时请求 `0700` 创建；
只在 host（agent）与终端生效，main 保持原值；`TMPDIR` 进 `SHELL_EXPORT_SKIP_KEYS`。
→ AF_UNIX 路径型 bind 在 `/storage/Users` 被虚拟化层拦截（EPERM），socket 不跟随 TMPDIR：
host 引导另建 `/data/storage/el2/base/files/tmp` 并经 `ZCODE_OHOS_SOCKET_DIR` 下发，
node-repl broker 优先使用该目录（其余 tmpdir 用法仍是文件操作，留在真实 home）。

**预装工具（上游 v4.0.0）在 OHOS 没有可用目标**。
→ `packages/desktop/src/preinstalled-tools/catalog.json` 只登记 darwin/arm64|x64，`loadPreinstalledToolsCatalog`
按 `process.platform/arch` 解析后为空，安装与回收流程不可达，main 的预装工具进程不会走到
`child_process`。UI 侧帮助菜单的「预装工具」入口已按 `platform.isOhos` 禁用（[21](./21-上游能力可用性清单.md) B 档），
等预装与文档转换链路适配后再放出。上游补齐 linux 目标前，若清单出现 `linux/arm64`，必须先给 main 域
调用点加 `isOhosRuntime()` 短路，再按 [15](./15-平台适配治理与不变量.md) 的门禁登记。

**agent 命令无缝：LD_PRELOAD exec shim（改写缺失解释器的 shebang）**。
→ agent 视图没有 `/usr/bin/env`，包管理器安装的 shim 脚本（`#!/usr/bin/env node`）会失败。
host 引导注入 `LD_PRELOAD=<bundle libs>/libzcode_exec_shim.so`（native/ohos-exec-shim），
Bash/MCP/插件子进程执行脚本时被改写为 `/bin/env …` 交 PATH 解析；解释器存在时透明。

```
main 引导 ── 采集 v3（cwd=realHome, 最小基线） ──落盘──► v2/ohos-login-env.json
host 引导 ── 有快照：PATH 整体替换 + 用户键覆盖；无快照：保持引导 PATH ──► agent Worker / Bash
终端      ── main 域 spawn `/usr/bin/zsh -il`（env 随 spawn 消息下发：快照 PATH/LD_PRELOAD/TMPDIR）
（快照由 main 每次启动重写；host 启动读到的可能是上一次的——下次启动自愈）
```

**终端 shell = Main 域托管**：native child（nativespawn）域没有 `/usr/bin` 且禁止 exec 非系统
ELF；host 域没有 `/usr/bin/zsh`，用户目录只可 exec「平台认可来源」的 ELF；main 域有系统
`/usr/bin/zsh` 且异步 spawn 可用。
→ 终端固定走 **Main 中继托管 shell**：main 以 `child_process.spawn` 起 shell（`/usr/bin/zsh -il`；
候选系统 zsh → main 落盘的 hint → `/bin/sh`），管道 stdio + 行级回显（无 tty，`\n` 补 `\r`）；
host env（快照 PATH、LD_PRELOAD、TMPDIR）随 spawn 消息下发。没有 native child 或 host 本地
管道回退；用户看到的 zsh 与 HiShell 里的交互 shell 同源。

**应用域裸 `ssh`/`scp` 不可用**：① `/storage/Users` 属主被虚拟化层固定为 20001006，ssh 读
默认路径 config 强制「属主==进程 uid」→ `Bad owner or permissions`；rc 里的 `ssh -F` alias
不在 env 里，spawn 的子进程继承不到。② host rootfs 视图无 `/usr/bin/ssh`。
→ 引导时在 `<realHome>/.zcode/bridge/bin/` 生成 `ssh`、`scp` wrapper（幂等；存在
`~/.ssh/config` 才生成；与用户自己的 bin 隔离；旧位置 `.zcode/bin` 上带生成标记的 wrapper
在 ensure 时清理，用户自放文件不动）。候选链 = `/usr/bin` → `/bin` → 运行时 PATH（登录快照，
排除 wrapper 自身目录），统一追加 `-F <realHome>/.ssh/config`；wrapper 目录**前置**进 PATH
（遮蔽系统 ssh）。应用内 `ssh hsl` 与用户 zsh 行为对齐；zcode 自身远程连接走 ssh2 库 +
`ssh -G -F`（`sshConfigAlias.ts`）不受此坑影响。

**OHOS 不是 Linux：UA 仍报 Linux；main 进程的同步 spawn 会终止应用**。
→ 渲染进程的 OHOS 判定由 preload 同步暴露 `window.zcode.isOhosRuntime`（UA 不可用），经
`IPlatformService.isOhos` 进入 UI——电脑控制用 `local-ohos` 文案分支；远程连接保留 Docker
入口，选中后提示「HarmonyOS 设备不支持 Docker 连接，请改用 SSH」并禁用连接（不发起探测）。
`desktopRuntimeEnv` 的两个 docker 探测经 `isMainProcessExternalCommandAllowed` 在动态导入前
短路；`ssh -G` 探测（`listSSHConfigAliasesFromLocalConfig`）在 OHOS 直接跳过 spawn，改用配置
文件解析结果。其余 main 侧 `child_process` 调用点由平台/功能门禁挡住，并由
`packages/desktop/test/desktopMainChildProcessGuard.test.ts` 做登记制防回归。**约束：OHOS 的
main 进程禁止同步 `child_process`（`spawnSync`、`process.binding("spawn_sync")`、executor 同步
路径）；异步 `spawn` 仅限已登记的登录 shell 采集与终端托管，新增调用点先判断平台并登记
`desktopMainChildProcessGuard`。**

**Node 20.18 无 `node:sqlite`；发行包自带绑定有三处缺陷**（写语句 run() 空转、裸命名参数绑
NULL；API 26 起数组整参绑定失效）。
→ 自有 NAPI 绑定 `zcode_sqlite.node`（C 源在 `packages/desktop/native/ohos-zcode-sqlite/`，
交叉编译，语义对齐 node:sqlite）优先，发行包绑定包装兜底；统一入口
`shared/nodeSqliteCompat.ts`，回归测试 `packages/shared/test/nodeSqliteCompat.test.ts`。约束：

- 候选路径覆盖两种安装布局：HNP/electron 物化布局走 `bundle/electron/…`（resfile 副本 +
  electron/libs）；HarmonyOS 7 PC 上 electron/libs 不物化，HAP 根 `libs/arm64-v8a` 被系统抽取
  归一化为 `bundle/libs/arm64`。**adapter 与 zcode 候选必须覆盖同一布局集**，否则首选后端
  静默落空、装机即崩。
- 打包必须双份复制（resfile app 根 + HAP libs；utility/host 进程的 `.node` require 有 loader
  重定向到 bundle libs，无 libs 副本则 host 进程加载失败）；产物缺失时 build-ohos.mjs 先自动
  编译（build.sh 自带 CLT clang 探测），失败即硬失败——静默 WARN 降级会产出装机必崩的包。
- 候选 `existsSync` 落空必须计入最终报错（probed-missing），否则看不到首选后端被跳过的痕迹。

**`/dev/ptmx` 对应用域被 SELinux 拒，无伪终端**（fork+exec 本身正常）。
→ shell 由 main 托管、经专用 MessagePort 与 host 中继（`desktopTerminalPtyRelay.ts` +
`ohosTerminalPty.ts`）。**缺的是 PTY 设备，不是 shell**：shell 仍是系统 `/usr/bin/zsh -il`，
日常命令、登录环境、cwd、别名与历史都正常；被 PTY 带走的是终端驱动层的四件事——
(1) 行规程（内核 echo、DEL、`\r`→`\n`，现在由应用层 `echoTransform`/`#normalizeOutput` 补）、
(2) 信号与作业控制（Ctrl-C/Ctrl-Z 不再由终端驱动转成 SIGINT/SIGTSTP，`fg`/`bg` 无意义）、
(3) `termios` 与窗口尺寸（`isatty()` 为 false、`cols/rows=0`、`resize()` 空实现）、
(4) 依赖前三者的全屏 TUI（vim/top/less 退化为 dumb 或直接报 not a terminal）。
OHOS 不走 node-pty，也不分发它的 OHOS prebuild。

**终端秒退会把 Host 整体拖死（任务/插件/模型列表永久转圈）**：管道 shell 秒退 → 终端注册表
即删 → renderer 晚到的 `terminal.onDynamicData` 订阅在 Host 的 RPC listen 处理器里同步抛
`Terminal not found` → Host `uncaughtException` → dispose + `exit(1)` → 窗口 workspace RPC
无人应答且 main 不重生。
→ 三层防护：`terminalService` 退出后保留短期墓碑（晚到订阅补发退出码、write/resize 幂等
丢弃）；`OhosRelayPty` 闩住早于订阅的退出事件；`packages/rpc` 的
`channelServer.onEventListen` 加异常边界（单个事件 getter 同步抛只杀该订阅）。另：
`PlatformChannels.LocalHostExited` 在 Host 意外退出时通知窗口，renderer 弹「重新加载窗口」
恢复入口（reload 后 dom-ready 走全新 spawn，旧宿主已从 windowHostProcessMap 摘除）。

**HAP 打包链过滤 resfile 里点开头的文件/目录 → 官方插件内容缺失**（`.zcode-plugin/`、
`.mcp.json` 丢失，插件协议以 `.zcode-plugin/plugin.json` 为存在性证据）。另：CLI 进程内
Worker 的 argv/`__dirname`/cwd 启发式定位不可靠，需宿主显式注入。
→ 双保险：① build-ohos stage 把点条目平铺成非点副本（`zcode-flat/plugin.json`、
`zcode-flat/mcp.json`，打包日志 `glm dot entries flattened` 计数），CLI（bundled-plugins.ts
`flatFileCanonicalPath`）反向还原为标准路径；② main 解析资源根 → `HostInitMessage.
bundledResourceDir`（fork env 在 OHOS 传不进 host）→ host 落
`process.env.ZCODE_BUNDLED_RESOURCE_DIR` → agent spawn env 透传到 Worker → CLI
`candidateBaseDirs()` 置顶该目录。seed 源缺失时每进程打一次 warn（带候选目录实际值）。
验证：应用内终端 `echo $ZCODE_BUNDLED_RESOURCE_DIR` 输出 glm 路径。

**`fs/promises.glob` 在 Node 20 ESM 链接期即崩**（命名导入存在性检查）。
→ `sshConfigAlias.ts` 运行时检测 `iterateGlobMatches()`，缺失回退字面量匹配。

**出站平台标识**：服务端不认 `openharmony` key → `isOhosRuntime()` 统一平台分支入口，
`mapOutboundPlatformKey()` 对外按 linux 上报；`process.title` 赋值 SIGSEGV、`app.isPackaged`
恒 false → `assignProcessTitle()` 收口 + 显式守卫。

**`shell.openPath(目录)` 在 OHOS 静默失效**：openPath 映射为 viewData Want，目录没有处理器
只会弹应用选择器；且 `LaunchHelper` 对 startAbility 失败只记 hilog、同步恒报成功。
→ `openPathInFileManager`（`desktopMainIpcHelpers.ts`）的 OHOS 分支改用 `shell.showItemInFolder`：
映射为 `filemanager://openDirectory` appLink（`FileManagerAdapter.openItemInFolder`），系统
文件管理器 `com.huawei.hmos.filemanager` 注册了该 scheme/host，可直接定位目录；
`openPathInDefaultApp` 对目录同样转 `showItemInFolder`。`shell.openPath(文件)` 的 viewData
语义对文件仍可用。

**「打开方式」下拉在 OHOS 为空**：mac Finder / win Explorer 以伪编辑器身份进入编辑器列表，
OHOS 编辑器 defs 为空；系统文件管理器是系统 ability，没有可 stat 的应用包路径，目录路径也
无扩展名、拿不到 UTD 文件图标。
→ `getEditorDefsForCurrentPlatform()` 的 OHOS 分支返回 `filemanager` 伪编辑器 def
（`openInEditor` 入口门禁要求 id 在列表内）；`getInstalledEditors()` 跳过路径探测与
`getFileIcon`，输出内联常量图标、名称按系统语言（zh「文件管理器」/en「Files」）；
`openInEditor()` 的 `filemanager` 分支复用 `shell.showItemInFolder`；UI 侧
`openWithEditors.ts` pin 列表加入 `filemanager`（「打开方式」置顶 + 工作区头部快捷按钮）。
第三方编辑器（VS Code 等）检测仍为后续项。

**Electron Notification 落为 OHOS 系统通知，生命周期长于应用**：适配层
`NotificationAdapter` 以 `notificationManager.publish` 发布，`tapDismissed:false`（点击不消除）

- 点击 WantAgent 拉起应用；系统通知归 DistributedNotificationService 所有，进程退出不会自动
  撤销。清理挂点：main 侧 `desktopNotifications.ts` 超上限逐出旧通知时同步 `close()`；OHOS 实际
  生效的清理在 ArkTS。

**Electron 的 quit 生命周期在 OHOS 不执行**：关窗后进程由系统直接终结，Node/Electron 的
`before-quit`/`will-quit`/`exit` 钩子不跑。
→ 依赖 quit 生命周期的清理移到 ArkTS `EntryAbility.onDestroy`（系统保证调用）；现行例：退出时
`notificationManager.cancelAll()` 撤销本应用全部通知。

**表快照迁移读 BLOB 时 host SIGSEGV（exit 11）**：迁移备份逐行哈希，`sort_key` 是 BLOB；自有
sqlite 绑定用 `napi_create_external_arraybuffer(…, NULL finalizer)` 输出 BLOB 时崩溃（且内存
永久泄漏）。
→ 改为 `napi_create_arraybuffer` + memcpy，迁移与备份正常通过。

**语音输入的麦克风权限**：入口与桌面对齐（`platform.supportsVoiceInput` +
`supportsMicrophoneCapture` 都为 true），识别走 zcode-server 的 ASR realtime。OHOS 的麦克风
授权由 ArkWeb 在 `getUserMedia` 时经适配层 `PermissionManagerAdapter`
（`'microphone' → ohos.permission.MICROPHONE`）触发，应用侧只需在 `module.json5` 声明该
user_grant 权限。失败路径见 [17](./17-语音输入.md)。

**凭据主密钥没有桌面钥匙串**（上游 `@napi-rs/keyring` 无 OHOS 产物）：Main 是唯一访问者，
主密钥存系统资产库 Asset Store；随包 NAPI 绑定 `ohos_asset_keyring.node` 与 sqlite 同布局
双份复制。资产库不可用时回退同目录 0600 私钥文件并打 warn，登录不会因此保存失败。密钥别名
按凭据文件路径摘要隔离数据根。详见 [16](./16-凭据安全存储.md)。
