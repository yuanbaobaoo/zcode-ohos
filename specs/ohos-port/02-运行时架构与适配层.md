# 02 运行时架构与适配层

移植过程按「遇到的问题 → 解法」记录；平台事实的根因见 [03](./03-平台权限与系统约束.md)。

## 进程模型

```
HAP（ai.ohpc.zcode）
 └─ main（Electron main，ArkTS EntryAbility 拉起）
     ├─ renderer / GPU（Chromium 子进程，XComponent 内 web 内容）
     └─ NodeService host（appspawn 拉起，不继承 main env）
         ├─ host 服务（会话/任务索引/存储）
         │   └─ agent CLI = 进程内 Worker（worker_threads 跑 zcode.cjs）
         └─ 终端会话池在 main（pty-main 中继）
```

## 问题 → 解法（按适配点）

**agent 无法独立进程**（exec 链路受限、HNP 随包安装被系统拒 9568407）
→ agent 以 host **进程内 Worker** 运行，stdio 管道模拟 ChildProcess；Worker `online` 事件映射为 spawn 事件，是 runtime lifecycle "available" 的触发源（任务列表依赖，勿删）。

**seccomp 拒 io_uring（syscall 425）→ 任一进程首次异步文件 IO 即 SIGSYS**，且 host 由 appspawn 拉起不继承 env、无法用 `UV_USE_IO_URING=0` 注入
→ 构建期对 libelectron.so 做 4 字节×2 二进制补丁禁用 io_uring（`ohos-patch-libelectron.mjs`，内容定位、幂等、纯 Node）。

**沙箱默认禁 RWX → V8 保留 CodeRange 直接 OOM**
→ 各进程入口早期 `loadNodeSqlite()` 加载随包 sqlite 绑定，其模块初始化 `prctl(PRCTL_SET_JITFORT)` 放开 JIT（agent 经 host env 继承）；Chromium 侧靠 `ALLOW_WRITABLE_CODE_MEMORY` 权限阻止 jitless 注入。

**HOME 对应用常无写权**（首个 logger mkdir 即 EPERM）
→ main 最早引导做**真实落文件**的写权探测（mkdir 成功不代表可写）；可写则以真实 home 为数据根，不可写先落应用沙箱保启动，首窗就绪后弹一次目录授权（ArkTS UriGrantHelper 持久化），授权后迁回。

**GUI 应用继承不到 HiShell 登录环境，agent 的非交互 spawn 不读 rc 文件 → brew 工具全不可见**
→ 共享模块 `services/ohos/ohosUserShellEnv.ts` 解析 `~/.zshenv/.zprofile/.zshrc` 的单行 export（PATH 按文件顺序重放），在 **main 与 host 双入口**各自执行（appspawn env 隔离），agent Worker 与 Bash 子进程经 env 继承；终端由 main 经 pty 中继下发。

**Node 20.18 无 `node:sqlite`，发行包自带绑定有两处缺陷**（写语句 run() 空转、裸命名参数绑 NULL）
→ 自有 NAPI 绑定 `zcode_sqlite.node`（C 源在 `packages/desktop/native/ohos-zcode-sqlite/`，交叉编译，语义对齐 node:sqlite）优先，发行包绑定包装兜底；统一入口 `shared/nodeSqliteCompat.ts`，回归测试 `packages/shared/test/nodeSqliteCompat.test.ts`。

**`/dev/ptmx` 对应用域被 SELinux 拒 → 无伪终端**（fork+exec 本身正常）
→ pty 改由 main 进程创建、经专用 MessagePort 与 host 中继（`desktopTerminalPtyRelay.ts` + `ohosTerminalPty.ts`）；ptmx 仍被拒时降级 stdio 管道 + 应用层行级回显的哑终端（无 vim/top 全屏，已知代价；平台开放后 node-pty 首选路径自动接管）。

**`fs/promises.glob` 在 Node 20 ESM 链接期即崩**（命名导入存在性检查）
→ `sshConfigAlias.ts` 改运行时检测 `iterateGlobMatches()`，缺失回退字面量匹配。

**出站平台标识**：服务端不认 `openharmony` key → `isOhosRuntime()` 统一平台分支入口，`mapOutboundPlatformKey()` 对外按 linux 上报；`process.title` 赋值 SIGSEGV、`app.isPackaged` 恒 false → `assignProcessTitle()` 收口 + 显式守卫。

## 已知限制

终端无全屏交互（哑终端）；`brew` 本体命令不可用（依赖 /proc/self/exe，装的工具不受影响）；无项目即席对话不入任务列表（与桌面版行为待对齐）。
