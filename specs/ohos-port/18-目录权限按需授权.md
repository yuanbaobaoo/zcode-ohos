# 18 目录权限按需授权

## 目标

1. **应用启动不主动请求任何权限**，不弹系统级授权窗口；
2. 仅当 Agent/用户实际需要 Desktop 时，才触发 Desktop 权限的系统授权；
3. 主页右下角常驻提示 + 引导页提示缺哪些权限，并提供「去授权」快捷按钮；
4. 全盘文件权限维持现状（手动设置面板，spec 08）。

## 背景（真机 2026-11-20）

权限只分两类：

- **全盘文件权限** `ACCESS_USER_FULL_DISK`（`manual_settings`）：覆盖 Desktop 之外的
  用户目录（含 Documents/Download），只能打开系统设置面板，不能应用内弹窗；
- **Desktop 目录权限** `READ_WRITE_DESKTOP_DIRECTORY`（`user_grant` / system_basic）：
  全盘权限不覆盖 Desktop（spec 03），必须单独声明并授权，系统可以弹窗确认。

历史上 Documents/Download 也声明过独立目录权限；本 spec 收敛为上述两类，
manifest 只保留全盘 + Desktop 两项（Documents/Download 由全盘覆盖）。

系统曾在「重装 + Profile ACL 变更」后对受限权限做一次性确认
（`com.huawei.hmos.security.privacycenter`）；这是系统行为，应用无法拦截，但
**不应由应用在启动路径主动触发**；
- 现有启动路径只调用了 `requestPermissionsFromUser(['READ_WRITE_USER_FILE'])`
  （system_grant，静默通过），本 spec 将该调用移除，启动路径零权限请求。

## 设计

### 状态

ArkTS 在窗口创建/回到前台时用 `checkAccessTokenSync` 查询 Desktop 权限，写桥文件
`desktop-access.json`：`{ granted: boolean }`；main 读取并 watch，renderer 通过
`platform.getOhosDesktopAccessStatus()` / `onOhosDesktopAccessChanged()` 获取。
非 Desktop-OHOS 返回 `supported:false`，UI 不出现。全盘权限状态沿用 spec 08 的桥。

### 按需请求

两个入口共用同一桥：

1. **用户主动**：右下角提示/引导页点「去授权」→ renderer 调
   `platform.requestOhosDesktopAccess()` → main 写 `desktop-access.request` → ArkTS
   轮询消费 → `requestPermissionsFromUser([READ_WRITE_DESKTOP_DIRECTORY])` → 系统弹窗。
2. **Agent 触发**：文件操作返回 `EPERM` 且目标在 Desktop 下时，host 写同一请求文件；
   ArkTS 消费后弹系统授权。非 Desktop 目录的 `EPERM` 归因于全盘权限未授予，走
   spec 08 的设置面板引导，不在本 spec 内弹窗。

同一时刻只允许一个待处理请求；授权结果由状态桥回流，UI 自动更新。

### UI

- 主页右下角：`OhosDesktopAccessPrompt`（Desktop 未授权时显示一个「授权桌面目录」按钮，
  可关闭）；全盘权限仍用 `OhosFullDiskAccessPrompt`。
- 引导页第 4 步：全盘权限卡片下方加 Desktop 权限状态与「去授权」按钮。
- 全盘权限的提示保持独立（设置面板，不是弹窗）。

## 验收

1. 冷启动（权限均已授予）不出现任何系统权限窗口；
2. 新装/重装后，系统对受限权限的一次性确认由系统触发，应用自身不得在启动路径请求；
3. 右下角/引导页能显示缺失目录并可一键触发对应系统授权；
4. 授权后状态自动刷新，按钮变为已授权；
5. Agent 访问未授权目录失败时，能触发对应授权而不是静默失败。
