# 18 目录权限按需授权

## 目标

1. 应用内**只引导全盘文件权限**，位置保持两处：引导页、主页右下角提示；
2. **不单独提示 Desktop 权限**，也不为它建应用内状态/请求桥；
3. Desktop 采用「代码无感」模型：代码正常读写 Desktop；若系统尚未授权，由**系统级
   授权弹窗**在访问时处理（例如把 Desktop 下的目录作为工作区、终端 `cd` 到 Desktop
   执行命令）。用户也可以在系统设置里手动开启，应用不做感知。

## 权限模型

| 权限 | 覆盖范围 | 授予方式 |
| --- | --- | --- |
| `ohos.permission.ACCESS_USER_FULL_DISK` | Desktop 之外的用户目录（含 Documents/Download） | `manual_settings`：系统设置面板；应用只做引导 |
| `ohos.permission.READ_WRITE_DESKTOP_DIRECTORY` | 仅 Desktop | `user_grant`：声明后由系统按访问/首次启动弹窗确认；应用不在启动路径主动请求 |

`module.json5` 同时声明两项，Desktop 权限还需随签名 Profile 的 allowed-acls 下发
（缺 ACL 安装报 9568289，spec 03）。Documents/Download 不单独声明目录权限，由全盘权限覆盖（实测可读写）。

## 应用内 UI

- **引导页第 4 步**：全盘权限说明、实时状态与「去开启」按钮（spec 08）；
- **主页右下角**：`OhosFullDiskAccessPrompt` 一次性提示（spec 08）；
- Desktop 没有独立卡片、按钮或提示；它的授权完全由系统弹窗承担。

## 启动行为

- 启动路径不调用任何 `requestPermissionsFromUser`；
- 冷启动（权限已授予）不出现系统权限窗口；
- 系统对受限 ACL 的一次性确认由系统在安装/首次访问时决定，应用不主动触发。

## Desktop 访问流程

1. 代码直接访问 Desktop 路径（工作区、终端 cwd、文件读写）；
2. 系统若判定未授权，弹出 Desktop 授权窗口；
3. 用户同意后访问继续（用户也可提前在系统设置里授予）；
4. 应用不检测、不缓存 Desktop 授权状态，也不写入请求文件——保持代码路径无感。

## 验收

1. 引导页/主页只有全盘权限提示，没有 Desktop 专属提示；设置页不提供全盘开关；
2. 冷启动无权限弹窗；
3. 把 Desktop 下的目录作为工作区、或在终端 `cd` 到 Desktop 执行命令时，未授权场景
   由系统弹窗处理，应用代码不需要额外请求；
4. Documents/Download 在只授予全盘权限时可读写。
