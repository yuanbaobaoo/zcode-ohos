# 碰一碰投送接收（华为分享 → 输入框附件）

手机（同华为账号、亮屏解锁）触碰 ZCode 窗口，把选中的图片/文档经华为分享投送到
应用；ZCode 将文件插入当前聚焦会话的输入框附件区，与「粘贴/选择文件」同一条上传
管线。官方机制：Share Kit《分享内容直达应用界面》——应用按 windowId 注册
`harmonyShare.on('dataReceive')`，沙箱接收（起始 6.0.0(20)，当前 compatibleSdk
6.0.2(22) 已覆盖，无需升 API 26，无新增权限/module.json5 声明）。

## 事件顺序与状态所有者

```
手机碰窗口（系统华为分享）
 → ① ArkTS ShareReceiveCoordinator（仅搬运，零业务状态）
      dataReceive 回调 → target.receive(<filesDir>/share-inbox/<batchId>/)
      onResult(SUCCESS) → 写 manifest.json（批次完整性的唯一事实）
 → ② main desktopOhosShareInbox（沙箱收件唯一所有者；幂等键=batchId）
      fs.watch（失败降级 2s 轮询）发现 manifest → 校验 → 整批移入
      <ZCODE_DATA_BASE_DIR>/share-inbox/<batchId>/ → 删沙箱批次
      → PlatformChannels.ExternalFilesReceived 发给聚焦窗口（发完即弃，不留状态）
 → ③ preload 接住并回放（与 ShareImport 同款冷启动保护）
 → ④ useRootPlatformEffects（onExternalFilesReceived）派发窗口 CustomEvent
 → ⑤ 聚焦 composer 的 useComposerAttachments 消费（preventDefault 认领，
      规则与白板 ADD_TO_CHAT 完全一致）→ addAttachmentLocalPaths
 → ⑥ composerAttachmentUploadStore 现有上传管线（零改动）
```

- 附件草稿所有者仍是 renderer composer scope（现状不变）；main 只搬运与转发。
- 全链路不新增 RPC、不碰 zcode-protocol、不影响手机远控/快照链路。
- 平台合同仅新增可选订阅 `onExternalFilesReceived?`（platform.ts 四类合法位置之一），
  Web 工厂不实现（可选成员），mac/win 将来可复用同链路接入「Open With/拖 Dock」。

## 边界与降级（产品规则）

| 场景 | 行为 |
| --- | --- |
| 类型不在能力声明（UTD 白名单） | 系统自动回落文件管理器，应用无感（官方兜底，不写代码） |
| 数量超 maxSupportedCount | 系统弹窗提示（系统行为） |
| 无聚焦 composer / 无匹配 workspace 消费 | 事件无人认领 → toast 提示，文件保留在数据根 inbox |
| 应用未运行（窗口不存在） | 物理上无可碰窗口，系统默认收进文件管理器 |
| manifest 损坏/文件缺失 | 丢弃该批（warn 日志），不部分注入 |
| 重复 manifest（同 batchId） | 幂等，只注入一次 |
| 收件目录残留 | 启动扫描回收；数据根 inbox 7 天 TTL 清理 |

## 验收

1. 真机伪 manifest E2E（无需手机）：向沙箱 inbox 写批次 → 聚焦会话输入框出现附件并
   走完上传生命周期；
2. 真手机投图片 1..N 张 / 文档各一 → 同上（发布前人工项）；
3. 类型不符 → 落文件管理器；超量 → 系统弹窗；
4. 同批次重放 manifest → 仅一次注入；
5. 无会话投送 → toast，文件在数据根 inbox；
6. node:test 覆盖 manifest 解析/批次校验/幂等/TTL 演算。
