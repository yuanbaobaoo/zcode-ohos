# 01 构建与打包

构建机：macOS（Linux 经 CI 验证同样可用）。真机经 USB + hdc 连接。

## 环境要求

| 项                      | 说明                                                                                                                                                                                                                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node 24.14 + pnpm 10.33 | 仓库标准工具链（mise）；`pnpm install`                                                                                                                                                                                                                                                                              |
| OHOS command-line-tools | **唯一额外必需**（hvigorw/ohpm/hdc），下载：[华为开发者下载页](https://developer.huawei.com/consumer/cn/download/)。三选一：`OHOS_COMMAND_LINE_TOOLS_ROOT`（推荐写入 `.env`，见 `.env.example`）/ 解压到 `~/command-line-tools` / `bin/` 加入 PATH                                                                  |
| Electron v40 运行时 | **不入库**：`libelectron.so`/`libadapter.so`/`libffmpeg.so`、启动器、resfile 的 pak/icudtl/快照/locales/vulkan 全部由 `fetch-ohos-runtime.mjs` 从 ohos-tools Release 的 `v40.0.1.20260928.2-release.zip` 提取并 sha256 校验（`ZCODE_OHOS_ELECTRON_URL` 可换源），首次构建/`dev:ohos` 自动执行。详见 specs/ohos-port/09 §12.5。 |
| 签名材料（可选）        | 无则只产出未签名 HAP；签名方法见下节                                                                                                                                                                                                                                                                                |

**不需要** DevEco Studio、devecocli、python3。

### 签名材料获取（二选一）

1. **AGC 手动**：控制台（developer.huawei.com）申请 debug 证书/Profile，复制 `build-profile.template.json5` 为 `packages/desktop/ohos/build-profile.json5`（机器相关、不入库），替换 signingConfigs.material 中 certpath/.p7b/.p12 为本机材料路径，密码填申请时所得。无签名材料时构建只产出 `*-unsigned.hap`（hvigor SignHap 自动跳过）；`build-profile.json5` 缺失时 bundle-ohos.mjs 自动复制模板。
2. **devecocli 捷径**（外部 npm 工具，非本项目依赖）：`packages/desktop/ohos/` 下执行 `devecocli auth login`（浏览器登录华为账号，一次性）→ `devecocli signature generate`（自动申请含受限 ACL 的 debug 证书），生成/更新 `build-profile.json5` 并指向 `~/.ohos/config` 材料（密码为加密串）。

### CI 工具链（.github/workflows/ohos-hap.yml）

- command-line-tools（Linux 版）：官方 26.0.0.851 原包分卷自托管在本仓库 ohos-tools Release（单资产超 GitHub 2GiB 上限故拆两卷，cat 合并），sha256 锁定校验；`OHOS_CLT_URL` 可覆盖为任意整包直链。
- Electron 运行时（三件 .so + 启动器 + resfile 资源）由 bundle 脚本从同源 Release 自动获取并校验。
- amd64 容器需 apt 安装 libgl1/libx11-6（HMS 工具链 `libimage_transcoder_shared.so` 运行时依赖，缺失 CompileResource 失败）；io_uring 补丁纯 Node 实现，无需 python3。

## 版本管理边界

`pnpm install`、`pnpm dev:ohos`、`pnpm bundle:desktop:ohos` 能生成的产物一律不入库：

- 依赖与构建缓存：`node_modules/`、`dist/`、`out/`、`oh_modules/`、`.hvigor/`、`build/`、`hnp/`
- 机器相关配置：根 `build-profile.json5`（含签名材料，只入库 `build-profile.template.json5`）、`AppScope/app.json5`
- HAP/resfile 组装产物：`web_engine/src/main/resources/resfile/resources/`
- Electron 运行时：三件 .so、启动器、`chrome_*.pak`、`icudtl.dat`、`resources.pak`、快照、`locales/*.pak`、`vulkan/`
- 原生终端产物：`native/ohos-zcode-pty/{libzcode_pty.so,zcode_ohos_process.node}`、HAP libs 里的 pty/zsh 镜像、`zcode_sqlite.node`

入库的是源码/模板/资产：`build.sh`、`.cpp`、`build-profile.template.json5`、字体与 OFL 等。锁文件（`pnpm-lock.yaml`、`oh-package-lock.json5`）保留入库以保证可复现。

例外：模块级 `<module>/build-profile.json5`（`entry`/`web_engine`/`account_quick_login`）不含机器信息，且 hvigor 在工程配置阶段强制要求，缺失即 `00304056 Not Found` 失败，必须入库；忽略规则因此锚定为根目录的 `/build-profile.json5`。

## 命令

```bash
pnpm bundle:desktop:ohos      # 打包：产物落 packages/desktop/dist/（未签名 + 可选签名版）
pnpm dev:ohos                 # 默认全量：dev HAP 装机到 hdc 可见的所有设备并启动（~30s；已装未装一律覆盖）
pnpm dev:ohos -- --build      # 全量闭环（~120s）：desktop 生产构建 + agent CLI 包（glm/zcode.cjs）一起重建。
                              # --build 必须隐含 agent 重建：glm 默认从 bundled-agents 旧产物 stage，
                              # 漏掉会把 apps/zcode-cli 的改动静默回退出包（曾致官方插件整体消失）。
pnpm dev:ohos -- --agent      # 只重建 agent CLI 包（改 apps/zcode-cli 后的快速迭代）。
pnpm dev:ohos -- --hqf        # 增量热推（单设备，需 --device 指定唯一目标）：变更 → 签名 hqf → quickfix → 重启（~8s）；
                              # 无基线/应用未安装/有删除/变更超阈值时自动回退全量

# 手动分步
node packages/desktop/scripts/build-ohos.mjs              # 构建产物 + resfile 组装
cd packages/desktop/ohos && hvigorw assembleHap --mode module -p product=default -p buildMode=debug --no-daemon
hdc install -r packages/desktop/ohos/entry/build/default/outputs/default/electron-default-signed.hap
hdc shell "aa start -a EntryAbility -b ai.ohpc.zcode"
```

CI：push `v*` tag 自动构建并发布未签名 HAP 到 GitHub Release。

## 常见坑

- **hvigor 增量不感知 resfile 变化**："1 秒构建成功"多半是缓存旧包。手动装机前清
  `packages/desktop/ohos/{.hvigor,entry/build,web_engine/build}`（bundle/dev 脚本已自动处理）。
- **设备锁屏时 `aa start` 报 10106102**：developer mode 不能自动解锁，手动解锁后重试。
- **应用日志**：console.log 进 hilog（tag `Electron`），但默认缓冲数十秒被系统日志滚没——
  `hdc shell "hilog -G 16M" && hdc shell "hilog -x -T Electron"`。
- **HAP libs 里的 .node/.so 被 hvigor strip 去符号**：md5 与源构建不同是正常现象，勿误判旧产物。
- **运行时调试**：`hdc fport tcp:9229 tcp:9229` 后开发机 Chrome `chrome://inspect` 全功能 DevTools。
- 真机 UI 自动化（CDP 通道）见 `packages/desktop/scripts/ohos-device-cdp.mjs` 头注。
