# 16 凭据安全存储

上游 v3.18.2 把凭据容器升级为 `enc:v2:`：主密钥放系统钥匙串（`@napi-rs/keyring`），Host 经凭据桥
向 Main 请求加解密。该原生包没有 OHOS 产物，本文固定鸿蒙侧的密钥落点与回退边界。

## 系统能力

HarmonyOS 的等价物是 **Asset Store Kit**：ArkTS 接口 `@ohos.security.asset`，native 接口
`<sdk>/native/sysroot/usr/include/asset/asset_api.h`（`libasset_ndk.z.so`，API 11+）。它提供
按别名存储的敏感字节（`ASSET_TAG_SECRET`），系统负责加密与访问控制，语义对应桌面钥匙串条目。
`HUKS` 管不可导出的密钥，不适合本场景：凭据容器需要取回一段可再派生的密钥文本。

## 决策

| #   | 决策                                                                      | 理由                                                                                   |
| --- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| D1  | 自有 NAPI 绑定 `ohos_asset_keyring.node`（`native/ohos-asset-keyring`）   | Node 侧不能直接调 ArkTS 接口；与 `zcode_sqlite.node` 同一构建/打包链，不引入文件轮询桥 |
| D2  | 主密钥条目别名 = `ZCode Credential Encryption:<sha256(凭据文件绝对路径)>` | 与桌面钥匙串「按数据根隔离」一致；换数据根得到新条目，不串用旧密钥                     |
| D3  | 仅 Main 访问资产库；Host/CLI 仍走上游凭据桥                               | 系统主密钥不进 Host/CLI，保持上游边界                                                  |
| D4  | 资产库不可用时回退同目录私钥文件（`credential-secret`，0600）             | 保证登录永远可保存；回退打 warn，不静默降级                                            |
| D5  | OHOS 构建不把桌面钥匙串原生包 stage 进 agent bundle                       | agent 以进程内 Worker 运行，凭据只经 Host→Main 桥；HAP 里不放其它平台二进制            |
| D6  | 回退与已绑定目录的自动重置交给上游全平台实现，OHOS 不再单独 bootstrap     | v4.0.0 起 Main 对全平台开启回退 + 重置；OHOS 只保留「选后端」这一层，减少分叉          |

> 跨包边界：D2 的别名只随凭据文件路径变化，资产库条目又**按应用（uid）隔离**，两个包共用同一数据根时会互相作废登录态（查不到密钥触发重置，或解不开对方密文）。开发包已改用独立数据根 `~/.zcode-dev`（[24](./24-开发包数据根与交付加固.md)），各自持有凭据文件与资产库条目；同一身份内换凭据文件路径仍会触发重置。

## 实现位置

```text
packages/desktop/native/ohos-asset-keyring/asset_keyring.c   资产库 NAPI 绑定（get/set/remove）
packages/desktop/native/ohos-asset-keyring/build.sh          交叉编译（与 sqlite 同一 SDK clang 探测）
packages/desktop/src/main/ohos/ohosAssetKeyStore.ts          CredentialKeyStore 适配（候选布局、别名）
packages/desktop/src/main/ohos/ohosCredentialBootstrap.ts    凭据 cipher factory（资产库 keyStore 注入）
packages/desktop/src/main/desktopHostProcess.ts              Main 侧唯一 cipher 创建点（factory）
packages/desktop/src/main/index.ts                           首次凭据访问前开启回退与自动重置（上游 v4.0.0 全平台统一）
packages/desktop/scripts/build-ohos.mjs                      自动编译 + 双份复制（app 根 + HAP libs）
```

打包布局与 `zcode_sqlite.node` 一致（spec 02）：`resfile/resources/app/`、`electron/libs/arm64-v8a/`、
`libs/arm64/` 三个候选都要能找到；缺 resfile 副本会让 HarmonyOS 7 PC 抽取布局下首选后端落空。

## 不变量

1. 资产库路径下主密钥明文不落盘；回退文件只允许同目录 0600。
2. 凭据文件路径是别名的唯一来源；不得用固定全局别名。
3. 密钥不经任何 RPC 暴露（上游 `CredentialCipher` 约束不变）。
4. 资产库失败必须走回退或抛出 `CREDENTIAL_SECURE_STORAGE_UNAVAILABLE`；禁止静默吞错。
5. 回退开关必须在首次凭据访问前开启；回退开启后不访问系统库。

## 运行行为

- HAP 内 `libs/arm64-v8a/ohos_asset_keyring.node` 经系统抽取后从 `/data/storage/el1/bundle/libs/arm64/`
  成功加载；resfile app 根的副本因 dlopen namespace 限制加载失败，属预期，候选链覆盖两种布局。
- `OH_Asset_Query` 首次返回 `ErrCode::NotFound`，随后 `Add` 成功；Main 与 Host 共用同一密钥，
  `web-remote-control` 取登录态成功，凭据以 v2 格式保存。
- 桌面端 `@napi-rs/keyring` 不出现在 HAP（构建期已裁剪），密钥只经资产库/私钥文件。

## 验收

- 真机：登录 → 保存凭据 → 杀进程重启 → 静默登录成功；`credentials.json` 内容为 `enc:v2:os:`。
- `ohos_asset_keyring.node` 在 HAP 的 app 根与 `entry/libs/arm64-v8a/` 各一份。
- 删除资产库绑定后启动：日志出现回退 warn，登录仍可保存（`enc:v2:env:` + `credential-secret`）。
- `pnpm typecheck` 通过；`ohosAssetKeyStore` 不参与 README/前端代码。
