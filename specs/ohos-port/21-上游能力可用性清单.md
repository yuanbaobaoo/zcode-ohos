# 21 上游能力可用性清单

同步上游之后，很多代码"在"，但在鸿蒙上要么跑不起来，要么跑法变了。这份清单把三种情况分开记：
直接用不了的、有入口但点不动的、能用但和上游不同的。排查问题时先来这里对照；上游下次同步时，
也别把已经改过的地方当成原样代码。

清单按 A / B / C 分。C 再拆两半：C1 是用户能感觉到的限制，C2 是内部实现换了做法（动这些地方前先看 C2）。
标 ▲ 的是这一轮 v4.0.0 同步才出现的项。上游没有、为鸿蒙新加的能力不在本文，见
[22-鸿蒙新增能力.md](./22-鸿蒙新增能力.md)。

维护：上游同步后逐项核对一遍，A/B 有变化就改这里；只要是换了机制的实现都进 C2，并把"上游怎么做、
我们怎么做、代价是什么"写清楚，免得下次同步照着上游把它改回去。

## A · 用不了

| 功能                            | 现状                                                       | 原因                                                                    |
| ------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------- |
| 自更新（下载、安装、重启）      | 整条链路关掉，只保留"查 GitHub Release → 浏览器打开发布页" | HAP 靠签名分发，没有 AppImage/deb 那种能自我替换的安装通道（spec 04）   |
| Windows 安装器、NSIS、入口 shim | 不出 NSIS 包，入口 shim 的路径一直是空的                   | 不是 Windows 目标（spec 02）                                            |
| Linux 系统包更新的 sudo 探测 ▲  | 判定恒为 false，永远走不到                                 | 平台报 linux 但不在 deb 通道上；而且 main 进程不能 fork+exec（spec 04） |
| 独立 CLI、TUI、SEA、npm 分发    | 都不做                                                     | 非交付面；`apps/zcode-cli` 在鸿蒙只作 HAP 内置的 agent 运行时           |
| Web、Server 独立部署            | 不打包也不发布                                             | 非交付面                                                                |
| iOS 模拟器插件                  | 插件装了，一跑预检就失败                                   | 预检要求 darwin 和 Xcode                                                |

## B · 有入口，但用不了

| 功能                               | 现状                                                                                 | 原因                                                              |
| ---------------------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 预装工具链 ▲                       | 帮助菜单入口保留但置灰，点了没反应；后台进程照常起，五个工具都"没有可用目标"，装不了 | 清单里只有 darwin/win32/linux 的目标，没有 linux-arm64（spec 02） |
| 文档转换（Office / PDF）           | 技能还在，真正执行时找不到托管 python 和 LibreOffice，报"预装未就绪"后停下           | 依赖上一条；系统里也没装这两样                                    |
| Chrome 数据导入                    | 设置里能点，但必然失败，报 `chrome_executable_not_found`                             | 探测只认 mac/win/linux 的 Chrome 安装路径                         |
| 桌面更新偏好（自动下载、预览通道） | 设置页这两项直接隐藏                                                                 | 没有自更新，留着也没用（spec 04）                                 |
| Docker 远程连接                    | 入口还在，选中就提示"鸿蒙设备不支持 Docker 连接"                                     | 设备上没有 docker CLI（spec 02）                                  |

> 2026-11-24 决策：预装工具链/文档转换**当前不适配、不排期**，B 档保持现状。调研摘要、与上游距离和未来重启条件见 [23-预装工具与文档环境适配.md](./23-预装工具与文档环境适配.md)；不要按旧方案实施。

## C · 能用，但和上游不一样

### C1 部分场景受限

| 功能                   | 还能用                                         | 受限                                                                                            |
| ---------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 终端                   | 系统 zsh，日常命令、登录环境、别名和历史都正常 | 没有 PTY：vim / top / less 这类全屏程序用不了，Ctrl-C 也中断不了，程序拿不到窗口尺寸（spec 02） |
| 会话活动时的关闭确认 ▲ | 关最后一个窗口会先弹确认                       | 走应用级 `before-quit` 的那条兜底在鸿蒙不执行，系统会直接终结进程（spec 02）                    |
| 裸 ssh / scp           | 能连                                           | 系统 ssh 的配置读不到，要靠引导期生成的 `-F` wrapper 把 PATH 垫在前面（spec 02）                |
| 窗口原生控件与标题栏   | 自绘控件，系统栏跟随深浅                       | 没有 macOS/Windows 那套原生 chrome，主题只有三态（spec 07）                                     |
| 原生"打开方式"列表     | 能用 `filemanager` 这个伪编辑器打开            | 系统应用列表探测是空的，第三方编辑器不会出现在列表里（spec 02）                                 |

### C2 实现换了机制

| 功能            | 上游怎么做                                                    | 鸿蒙怎么做                                                                                             | 代价                                                                                                               |
| --------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 托盘/关闭驻留   | Linux 用 StatusNotifier/DBus；Windows 用 Tray                 | main 在 OHOS 创建 Tray（PNG 图标）并放行 `canHideToTray`；ArkTS 状态栏条目删除，统一由 Tray 管理       | 状态栏菜单由系统渲染；系统会追加一个“退出”，模板不再自带 quit（spec 02 §22）                                       |
| 系统钥匙链      | `@napi-rs/keyring`                                            | 自建 Asset Store 绑定，组件缺失时回退到同目录 0600 私钥文件                                            | 回退时凭据标 `enc:v2:env:`（spec 16）                                                                              |
| 数据库          | Node 内置 `node:sqlite`                                       | 自研 NAPI 绑定，外面加一层兼容层                                                                       | 超过 2^53 的整数会返回 BigInt；写语句的参数要内联进 SQL（spec 02）                                                 |
| agent 进程      | 独立子进程加 stdio 管道                                       | host 进程内的 Worker，用伪管道桥接                                                                     | agent 侧不能 `console.log`；worker 的 `exit` 有时不触发（spec 02）                                                 |
| 用户 shell 环境 | 直接继承登录 shell                                            | main 先采一份 `zsh -ilc env` 快照，host 启动时合并                                                     | 只有快照这一个来源；首窗最多等 4s（spec 02）                                                                       |
| 脚本 shebang    | 系统自带 `/usr/bin/env`                                       | `LD_PRELOAD` exec shim 在执行时改写 shebang                                                            | 只在 agent 视图生效（spec 02）                                                                                     |
| 临时目录        | `/tmp`                                                        | `~/.zcode/tmp`                                                                                         | 只对 host 和终端生效，main 还是原来的值（spec 02）                                                                 |
| unix socket     | 工作区里的路径                                                | el2 下的 socket 目录（`ZCODE_OHOS_SOCKET_DIR`）                                                        | 两套目录并存，别混用（spec 02）                                                                                    |
| io_uring        | libuv 默认打开                                                | 构建期给 `libelectron.so` 打二进制补丁关掉                                                             | 换 Electron 端口要重新锚定（spec 02）                                                                              |
| JIT 内存        | 沙箱允许 RWX                                                  | 靠 sqlite 原生绑定初始化时的 `prctl(jit)` 解锁                                                         | 解锁动作寄生在原生绑定里（spec 02）                                                                                |
| 电脑控制        | macOS Helper 进程加 broker socket                             | 进程内 runtime、ArkTS 文件桥、`@ohos.screenshot`                                                       | 没有独立进程；权限按"辅助操作 + 截屏"两项聚合（spec 13）                                                           |
| 设备通道        | 官方 `hdc` server                                             | 随包的 `hdc-direct` CLI 直连 hdcd                                                                      | 自成仓库，单独发版（spec 11）                                                                                      |
| 更新检查        | electron-updater 下完自己装                                   | 查 GitHub Release（API → atom → 镜像三级降级），再开浏览器下载                                         | 不能自动装；请求必须直连（spec 04）                                                                                |
| 目录与全盘授权  | macOS 的 TCC 授权框                                           | ArkTS `UriGrantHelper` 持久化授权，再用桥文件把状态送回来                                              | 先落沙箱保证能启动、授权后迁回；按需弹一次（spec 08、18）                                                          |
| 系统栏主题      | `nativeTheme`                                                 | ArkTS `setColorMode` 三态，加窗口主题桥文件                                                            | 只能深浅跟随，不随内容自适应（spec 07）                                                                            |
| 打开目录        | `shell.openPath`                                              | 改成 `shell.showItemInFolder` 定位                                                                     | 目录从"打开"变成"定位"（spec 02）                                                                                  |
| 麦克风权限      | `systemPreferences` 申请                                      | ArkWeb 在 `getUserMedia` 时经 PermissionManagerAdapter 申请                                            | 授权时机从点按钮前挪到采集时；拒绝后没有"去设置"引导（spec 17）                                                    |
| 进程标题        | `process.title` / `app.setName`                               | 走共享的 `assignProcessTitle` guard，鸿蒙下不调 `setName`                                              | 进程名不按上游逻辑设置                                                                                             |
| 资源路径判定    | `app.isPackaged`                                              | 加一个 `isOhosRuntime()` 的兜底                                                                        | 鸿蒙的开发态也走打包路径                                                                                           |
| 版本号来源      | `app.getVersion()`                                            | 读构建产物 `build-meta.json` 里的 `ohosReleaseVersion`                                                 | 版本的事实源变成构建元数据（spec 04）                                                                              |
| 退出清理        | `before-quit` / `will-quit`                                   | ArkTS `EntryAbility.onDestroy`                                                                         | 挂在 main 里的退出清理在鸿蒙不会跑（spec 02）                                                                      |
| 剪贴板图片      | Electron 44 的 `ClipboardItem`                                | 回退到 `clipboard.writeImage`；鸿蒙走 UDMF pixelmap                                                    | 已验证可用：`writeImage` 后 `availableFormats()=["image/png"]`、`readImage()` 可读回                               |
| 浏览器控制桥    | node_repl 的浏览器代理 socket 用 `tmpdir()`（`~/.zcode/tmp`） | 与 `znr`/`znrc` 同规则落 `ZCODE_OHOS_SOCKET_DIR`（el2 tmp）                                            | 真实 home 上 AF_UNIX bind 被拦；必须由 host 下发该目录                                                             |
| 浏览器截图      | CDP `Page.captureScreenshot`                                  | main 直接 `webContents.capturePage()`：viewport/clip 直读；fullPage 滚动分段 capturePage + main 行拼接 | CDP 截图在端口上 SIGTRAP；CDP metrics override 不改变 guest surface（真机实测仍只返回视口），已改滚动分段 + 行拼接 |
| 官方插件缓存    | 按 `version` 目录 seed，内容变化靠版本号换目录                | 同步 bump `node-repl-host` 的 package/plugin/catalog 版本                                              | 只改代码不 bump 版本时，旧缓存会被判定可用，修复不会下发（真机实证）                                               |
| 模拟器渲染      | 直接用 GPU 加速                                               | 按设备判据切 ANGLE 加 SwiftShader，三态可配                                                            | 模拟器上是软件渲染，有性能代价（spec 06）                                                                          |
