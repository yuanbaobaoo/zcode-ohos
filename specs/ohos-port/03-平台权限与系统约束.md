# 03 平台权限与系统约束

适配层依赖的**平台事实清单**：每条约束对应代码中的对策，破坏对策会崩溃或功能回退。改适配层代码前先过一遍本文。

## 系统权限（module.json5）

| 权限                                            | 作用                                              | 缺失后果                                                                 |
| ----------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------ |
| `CUSTOM_SANDBOX`（ACL）                         | 允许 exec **用户目录 ELF**——brew 工具链可用的前提 | 终端/agent 执行 brew 工具报 EPERM（toybox 文案与"未安装"相同，注意甄别） |
| `kernel.ALLOW_WRITABLE_CODE_MEMORY`（受限 ACL） | 阻止 libadapter 向 Chromium 进程注入 jitless      | renderer 退回解释执行，WebAssembly 不存在                                |
| `READ_WRITE_USER_FILE`（user_grant）            | 读真实用户 home（rc 文件、.harmonybrew）          | 用户 shell 环境注入失效                                                  |
| `ACCESS_USER_FULL_DISK`（manual_settings）      | 全盘访问；不弹系统框，需引导用户到设置页开启      | 沙箱外文件不可读                                                         |

ACL 类权限由 debug Profile 携带（签名材料生成时申请）。

## V8 / NAPI：Smi 参数铁律（最重要）

libelectron 的 V8 为间接 Local ABI，而 `v8::Object::Get` 的 Smi 快路径返回**裸 tagged 值**——任何数字经 `napi_get_element/get_property` 进入 native 即 SEGV（被当槽位地址二次解引用）。

- 安全通道：字符串/对象/BigInt、`napi_get_cb_info` 位置参数（argv）；
- 对策：sqlite 包装层把数组/对象参数展开为位置参数；**新增任何 NAPI 取值路径必须维持"数字只走 cb_info 通道"**。

## 内核 / 沙箱约束

| 约束                          | 事实                                               | 对策                                                        |
| ----------------------------- | -------------------------------------------------- | ----------------------------------------------------------- |
| io_uring 被 seccomp 拒        | syscall 425 → SIGSYS；host 不继承 env 无法注入变量 | 构建期二进制补丁（见 02）                                   |
| el1 bundle noexec             | HAP 安装区 ELF 不可 exec（随包 zsh X_OK 可过但起不来） | 终端 shell 候选系统 zsh 优先（PC 真机可见可 exec），不可见设备落随包/sh 回退（见 02） |
| ptmx 被拒                     | openpty/forkpty 不可用                             | main 中继 + 哑终端降级（见 02）                             |
| `/storage/Users` 顶层不可枚举 | readdir/glob 返回空，子目录直访正常                | harmonybrew 前缀直接探测标准路径 `currentUser/.harmonybrew` |
| appspawn env 隔离             | host 不继承 main env                               | 用户 shell env 双入口重放（见 02）                          |
| 用户目录 ELF 默认禁 exec      | debug_hap 域 MAC 拦截                              | `CUSTOM_SANDBOX`；全流程保持本地 debug 签名即可             |
| 用户文件属主被虚拟化层固定    | `/storage/Users` 下属主恒为 20001006(file_manager)≠应用 uid，chmod/chown 均被忽略（chmod 600 落成 660）。ssh 读**默认路径** config 时强制「属主==进程 uid」→ `Bad owner or permissions` 退出，与权限位无关；`-F` 显式指向同一文件可跳过校验（真机实证：`Host` 别名 / `IdentityFile` / `known_hosts` 均正确解析） | ssh/scp wrapper 统一加 `-F`（见 02） |
| main 与 host rootfs 视图不对称 | main（Electron 壳）可见并可 exec `/usr/bin/zsh`（5.9）、`/usr/bin/ssh`；host（appspawn NodeService）namespace 内这些文件**不存在**（PATH 含 `/usr/bin` 但 ENOENT）。用户目录 ELF（brew 工具链）两端均可 exec | 系统工具走 wrapper 候选链（brew → 系统）；登录 shell 快照仅 main 采集（见 02） |
| 同步 spawn 拦 clone3，异步不拦 | host **同步** spawn（execFileSync）拦 clone3 整进程 SIGSYS（crash dump 实证）；main **异步** spawn（终端、环境探针、`zsh -ilc env`）真机全部正常 | 快照采集/探针一律异步 spawn；勿在 host/utility 用同步 spawn 探测 |
| `/tmp` 对应用域只读           | 应用进程写 `/tmp` 报 Read-only file system         | 临时文件走 `$TMPDIR`（应用 cache）或数据根                  |

## 工具链行为

- hvigor 增量不感知 resfile/libs 变化 → 装机迭代前清缓存（脚本已自动）；
- HAP libs 的 .node/.so 会被 strip 去符号 → 对账用行为验证，勿按 md5 误判；
- `app.isPackaged` 恒 false（exec 名是 electron）→ 打包态分支用 OHOS 显式守卫；
- tsup 失败不回滚 out/ → 构建有 error 时勿装机。
