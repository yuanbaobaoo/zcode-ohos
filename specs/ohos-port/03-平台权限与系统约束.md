# 03 平台权限与系统约束

适配层依赖的**平台事实清单**：每条约束对应代码中的对策，破坏对策会崩溃或功能回退。改适配层代码前先过一遍本文。

## 系统权限（module.json5）

| 权限                                            | 作用                                              | 缺失后果                                                                 |
| ----------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------ |
| `CUSTOM_SANDBOX`（ACL）                         | 允许 exec **用户目录 ELF**——brew 工具链可用的前提 | 终端/agent 执行 brew 工具报 EPERM（toybox 文案与"未安装"相同，注意甄别） |
| `kernel.ALLOW_WRITABLE_CODE_MEMORY`（受限 ACL） | 阻止 libadapter 向 Chromium 进程注入 jitless      | renderer 退回解释执行，WebAssembly 不存在                                |
| `READ_WRITE_USER_FILE`（user_grant）            | 读真实用户 home（rc 文件、.harmonybrew）          | 用户 shell 环境注入失效                                                  |
| `ACCESS_USER_FULL_DISK`（manual_settings）      | home 以外未授权路径的读写；不弹系统框，引导链路见 [08](./08-全盘文件权限引导.md)（启动不弹窗） | 沙箱外文件不可读                                                         |

ACL 类权限由 debug Profile 携带（签名材料生成时申请）。

## V8 / NAPI：Smi 参数铁律（最重要）

libelectron 的 V8 为间接 Local ABI，而 `v8::Object::Get` 的 Smi 快路径返回**裸 tagged 值**——任何数字经 `napi_get_element/get_property` 进入 native 即 SEGV（被当槽位地址二次解引用）。

- 安全通道：字符串/对象/BigInt、`napi_get_cb_info` 位置参数（argv）；
- 对策：sqlite 包装层把数组/对象参数展开为位置参数；**新增任何 NAPI 取值路径必须维持"数字只走 cb_info 通道"**。

## 内核 / 沙箱约束

| 约束                          | 事实                                               | 对策                                                        |
| ----------------------------- | -------------------------------------------------- | ----------------------------------------------------------- |
| io_uring 被 seccomp 拒        | syscall 425 → SIGSYS；host 不继承 env 无法注入变量 | 构建期二进制补丁（见 02）                                   |
| el1 bundle noexec             | HAP 安装区 ELF 不可 exec（随包 zsh X_OK 可过但起不来） | 终端 shell 候选系统 zsh 优先（PC 真机可见可 exec），不可见设备落随包/sh 回退（见 02） |
| ptmx 被拒                     | openpty/forkpty 不可用                             | main 中继 + 哑终端降级（见 02）                             |
| `/storage/Users` 顶层不可枚举 | readdir/glob 返回空，子目录直访正常                | harmonybrew 前缀直接探测标准路径 `currentUser/.harmonybrew` |
| appspawn env 隔离             | host 不继承 main env                               | 用户 shell env 双入口重放（见 02）                          |
| 用户目录 ELF 默认禁 exec      | debug_hap 域 MAC 拦截                              | `CUSTOM_SANDBOX`；全流程保持本地 debug 签名即可             |
| 用户文件属主被虚拟化层固定    | `/storage/Users` 下属主恒为 20001006(file_manager)≠应用 uid，chmod/chown 均被忽略（chmod 600 落成 660）。ssh 读**默认路径** config 时强制「属主==进程 uid」→ `Bad owner or permissions` 退出，与权限位无关；`-F` 显式指向同一文件可跳过校验（真机实证：`Host` 别名 / `IdentityFile` / `known_hosts` 均正确解析） | ssh/scp wrapper 统一加 `-F`（见 02） |
| 子进程视图由启动方式决定 | main / GPU 由 appspawn 拉起（ppid 660），`/usr/bin` 是完整 toybox 软链农场（`env → /system/bin/toybox`）；Renderer / NetworkService / NodeService 由 `nativespawn` 拉起，`/usr/bin` 是 **0411 空挂载**，`/usr/bin/{env,sh,curl,ssh,zsh}` 全部 ENOENT（`/bin` toybox 可用）。用户目录 ELF（brew 工具链）两端均可 exec | agent 内用 `/bin` 或 brew 工具；自带脚本由执行端显式调解释器；根治见下方「nativespawn 视图修复」 |
| main 进程 `child_process` 会终止应用 | 2026-10-22 模拟器隔离实验：`execFile`/`spawn` 任意目标（`/bin/echo`、`/bin/true`、缺失的 `docker`）均在调用内同步死亡，appspawn 报 `exit with signal:6`，无 JS 异常、无 cppcrash；只加载 `node:child_process` 不 spawn 则存活；异步不豁免。host 的**同步** spawn 另有 clone3 SIGSYS（crash dump 实证） | OHOS 的 main 禁用 `child_process`：探测先判平台，子进程能力走 appspawn native child / pty 中继（见 02）。早期真机记录称 `zsh -ilc env` 异步 spawn 可用，但模拟器无法复现，按禁用处理 |
| `/tmp` 对应用域不可写         | `/tmp` 属主 uid 1076、`0770`(sticky)，应用 uid 20020228 无写权（2026-10-27 真机实测） | agent/终端 `TMPDIR=<realHome>/.zcode/tmp`（同 `/storage/Users` 文件系统，避免 `EXDEV`），main 保持原值（见 02） |
| 未签名来源的 ELF 副本被拦 exec | 真机（2026-10-27）：随包 zsh 的副本（HAP libs `libzsh.so`、el2、用户 home、native child/host/main 各域）一律 `EACCES`；**brew 安装的 bash 副本**在同目录/同权限（0770 gid 1006）下可正常 exec。脚本（ssh wrapper，同权限）也可 exec | 终端 shell 直接使用系统 `/usr/bin/zsh`（main 域托管，见 02）；不再分发随包 shell 二进制 |
| 系统 zsh 仅 main 域可见 | `resolveOhosBundledZshPath` 在 main 视图命中 `/usr/bin/zsh`；host/native child 域 ENOENT | 终端 shell 由 main 托管；host 仅作本地管道回退（brew bash → /bin/sh） |
| `/etc/profile` 在应用域被拒 | bash 登录链（`-il`）读 `/etc/profile` 报 Permission denied，且用户 `.profile` 会 `exec zsh`（未安装时整链失败） | 终端 bash 用 `-i` 不加 `-l`；zsh 走自己的 `.zshrc`（`-il`） |
| AF_UNIX 路径 bind 被拦截      | `/storage/Users` 上 `listen()` 报 EPERM（真机实证 `znr-*.sock`，用户 rc 亦记录 tmpfs+hmmac 限制）；socket 必须落应用 el2 区 | host 引导建 `/data/storage/el2/base/files/tmp` 并经 `ZCODE_OHOS_SOCKET_DIR` 下发；broker 优先使用（见 02） |
| 管道执行合并 stderr→stdout    | agent 的 Bash 工具在 OHOS 走管道回退，失败时 `stderr` 为空、错误文本在 `stdout`（真机实证 exit=126） | 依赖 stderr 判定的适配逻辑必须同时检查 stdout（对方先例：ohos-bash-diagnostic） |

### nativespawn 视图修复（未解，adapter 侧）

真机对照（2026-10-27）：

```
/proc/<main>/root/usr/bin/env        → /system/bin/toybox      (存在)
/proc/<main>/root/usr/bin/{sh,curl}  → 存在
/proc/<node>/root/usr/bin            → mode 0411，readdir EACCES
/proc/<node>/root/usr/bin/env        → ENOENT
```

修复优先级：

1. **V1**：让 Chromium 子进程走 appspawn 语义（`runArkProcess` 原地 exec，或改用 `startArkChildProcess` 路径），使 NodeService 继承 appspawn 的完整挂载；
2. **V2**：nativespawn 沙箱纳入 `/usr/bin`（系统侧，需厂商）；
3. **V3**（zcode 内备选）：host 改为 main 直接 `child_process.fork`，靠父进程视图遗传；代价是消息通道与崩溃处理重做。

已核实的边界（2026-10-27）：平台侧没有可用的挂载开关——ArkTS `childProcessManager.startNativeChildProcess` 的 options 只有 `isolationMode/isolationUid`；模块配置 schema 无 native child / sandbox / mount 字段。启动链路落在 vendor 预编译的 `libadapter.so`（`ChildProcessManager::StartNativeChildProcess(WithName)` → `OH_Ability_StartNativeChildProcess*`）与 `libelectron.so` 进程启动器内，本仓只能改 ArkTS 层，因此 V1/V2 需厂商侧改动；V3 依赖 main 进程 spawn（平台规则按禁用处理）。

验收：agent 内 `test -x /usr/bin/env`、`pnpm -v`、直接执行 `#!/usr/bin/env node` 脚本。

### LD_PRELOAD exec-shim（agent 命令无缝，不依赖厂商）

nativespawn 视图里 `/usr/bin` 是只读空挂载，既不能造文件也不能 mount；改成**在 exec 出口改写**：
`native/ohos-exec-shim/exec_shim.c`（HAP libs 的 `libzcode_exec_shim.so`）拦截
`execve/execv/execvp/execvpe/posix_spawn(p)`，解析 shebang；解释器缺失时改写成
`/bin/env <命令> <脚本>` 交给 PATH 解析（`#!/usr/bin/python3` 这类硬编码路径同样覆盖），
解释器存在时完全透明（adapter 修复后自动空转，无需撤除）。

- 注入：host 引导 `LD_PRELOAD=<bundle libs>/libzcode_exec_shim.so`，只作用于继承该 env 的进程树（Bash/MCP/插件子进程）。
- **预加载只认 bundle 内库**：用户目录路径被 OHOS 加载器忽略（真机实证：放入 el2 用户目录、甚至不存在的路径都不报错、也不加载）；LD_LIBRARY_PATH 不受此限。
- 边界：host/CLI 进程自身（LD_PRELOAD 需启动时注入）与不经我们 env 的 exec 不受覆盖；覆盖不到时仍有 Bash 侧提示（见 02）。
- **真机验收（2026-10-27）**：agent 里 `pnpm -v` → `10.33.2`（此前连续多次 exit 126）；`#!/usr/bin/env node` 脚本直接执行输出 `123`（exit 0）。附带观察（与 shim 无关，待单独排查）：CLI 启动脚本调用 resfile 下的内置 `ugrep` 报 `Permission denied`，属 resfile noexec 的既有约束。

## 工具链行为

- hvigor 增量不感知 resfile/libs 变化 → 装机迭代前清缓存（脚本已自动）；
- HAP libs 的 .node/.so 会被 strip 去符号 → 对账用行为验证，勿按 md5 误判；
- `app.isPackaged` 恒 false（exec 名是 electron）→ 打包态分支用 OHOS 显式守卫；
- tsup 失败不回滚 out/ → 构建有 error 时勿装机。
