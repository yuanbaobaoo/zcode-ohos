# 08 全盘文件权限引导（一次性 toast + 设置页开关）

`ACCESS_USER_FULL_DISK` 是 manual_settings 权限（对应系统设置「访问全盘文件」开关），`requestPermissionsFromUser` 对它不弹窗，只能检测状态 + 引导用户到系统面板开启。

## 背景与裁定的平台事实

- 旧行为：`EntryAbility.onWindowStageCreate` 在窗口创建后立即弹应用内 AlertDialog 索要全盘权限，「暂不」不持久，每次冷启动重复弹。
- 实测证据（装机排障时间线 #15）：brew 工具链 exec 的解锁来自 `CUSTOM_SANDBOX`（system_grant，装机即授，从不弹窗）；**授予全盘权限对 brew exec 无效**。rc 文件 / `.harmonybrew` / `~/.ssh/config` 的读取依赖 `READ_WRITE_USER_FILE`（安装即授）。
- 结论：全盘权限不守护核心功能（编辑器、agent、已授权工作区、brew/HiShell 环境均不依赖它），真实价值是「终端/agent 访问 home 以外且未经选择器授权的任意路径」。启动即弹属于过度索要。

## 产品规则

1. 启动与窗口创建路径不出现任何全盘权限相关界面（ArkTS AlertDialog 移除）。
2. **一次性 toast**：首次进入主页面（判定＝App 挂载；登录页 WelcomeScreen 期间 App 不挂载，天然排除）且当时未授权，在右下角弹一次应用内 toast：说明用途 +「去开启」按钮。**不自动消失**——只有用户点关闭（×）才消失；「去开启」后 toast 保留（状态由轮询回流，设置页开关可见结果）。**不得另设登录态门槛**——API Key 模式跳过登录后无 user 对象也要弹。弹出即持久化已展示标记（renderer localStorage），之后任何启动/会话都不再弹。「清除应用数据」后标记随 localStorage 重置，视为全新安装。
3. **常驻入口**：设置 → 常规 → 数据存储路径下方显示「开启全盘文件权限」开关（能力合同驱动显隐）。开关**任何状态都可点击**：未授权时点击拉起授权引导；已授权时点击同样触发（本运行时授权面板 API 对 manual_settings 失败，自动落到跳系统设置页，用户在系统设置关闭；系统关闭该权限需强停应用，属平台行为）。开关显示态始终反映真实授权。
4. **引导页说明**：职业引导向导（OccupationOnboarding，设置 → 引导 可重开）在末尾追加「鸿蒙系统环境介绍」一步（仅 OHOS 显示）：说明全盘权限用途/不开启的影响 + 当前授权状态 + 「跳转」按钮（触发同一授权引导链路，状态经轮询回流实时刷新）。导航规则：偏好页（原末页）「跳过」不结束引导，而是进入鸿蒙页，跳过语义（偏好按未选择记录）保留到鸿蒙页「开始使用」时生效；鸿蒙页作为末页**不显示跳过按钮**，只有「开始使用」。
4. **状态回流**：用户从系统设置返回应用（`onForeground`）时 ArkTS 重查并改写状态，renderer 经推送自动刷新（toast 期间授权成功不额外弹成功提示，开关状态即可见）。
5. 点击「去开启」不乐观翻转任何 UI 状态；以系统真实授权状态为唯一事实。

## 状态所有者与链路

```text
ArkTS EntryAbility（状态唯一采集者）
  │ onWindowStageCreate / onForeground：checkAccessToken(ACCESS_USER_FULL_DISK)
  │ 写桥文件 <haps/electron/files>/full-disk-access.json { granted, updatedAt }
  ▼
main desktopOhosFullDiskAccess.ts（桥文件读者 + fs.watch 推送）
  │ IPC：OhosFullDiskAccessStatus(invoke) / OhosFullDiskAccessChanged(send)
  ▼
preload window.zcode → desktopPlatform（IPlatformService 可选方法）
  ▼
packages/ui：OhosFullDiskAccessPrompt（一次性 toast）+ SettingsPage 开关

授权触发（renderer → ArkTS，方向相反，请求文件通道）：
  OhosFullDiskAccessRequest(send) → main 写 <haps/electron/files>/full-disk-access.request
  EntryAbility 前台 1s 轮询发现请求文件：删除 + requestPermissionOnSetting 拉系统面板
  （requestPermissionOnSetting 失败时 startAbility 跳应用信息设置页兜底）
```

- 桥文件路径约定与 window-theme 桥一致：main 侧写死 `/data/storage/el2/base/haps/electron/files`（ArkTS `this.context.filesDir` 的模块级形态，见 07 的目录说明）。
- 「已展示标记」归 renderer（localStorage key `zcode.ohos.fullDiskPromptShown`）；「授权状态」唯一事实是系统授权，桥文件只是它的投影。
- `READ_WRITE_USER_FILE` 的静默 `requestPermissionsFromUser` 保留在 onWindowStageCreate（装机即授，不弹窗）。

## 接口

- 触发通道（请求文件，真机实证定案）：**iframe / window.open 导航自定义 scheme 在 OHOS Electron 上均静默失败**（无 onNewWant、无外部协议分发），不能用 web 侧导航触发系统能力。改为 renderer `OhosFullDiskAccessRequest` IPC → main 落 `full-disk-access.request` → EntryAbility 前台轮询（1s）消费并拉 `requestPermissionOnSetting`；失败兜底跳应用信息设置页。
- IPC（`packages/shared/src/channels.ts`）：
  - `OhosFullDiskAccessStatus`（invoke → OhosFullDiskAccessStatus）：main 读桥文件；文件不存在/损坏视为未授权（与系统真实状态的下一次 ArkTS 写入对齐）。
  - `OhosFullDiskAccessChanged`（main→renderer send）：桥文件 fs.watch 变更推送。
  - `OhosFullDiskAccessRequest`（send → void）：main 写请求文件。
- `IPlatformService`（均为可选，仅 Desktop-OHOS 实现）：`getOhosFullDiskAccessStatus()`、`onOhosFullDiskAccessChanged(handler)`、`requestOhosFullDiskAccess()`。

## 真机验证记录（模拟器 127.0.0.1:5555，2026-10-15）

1. ✅ 状态链路：撤权后冷启动，`getOhosFullDiskAccessStatus()` 返回 `{supported:true, granted:false}`（ArkTS 写桥文件 → main 读全通）。
2. ✅ 一次性 toast：清 localStorage 标记 + reload 复现，右下角渲染「建议开启…」+「去开启」；标记写入后不再弹。曾发现 bottom-right 容器缺失 bug（ToastHost 未渲染该位置栈，toast 被静默丢弃），已修复。
3. ❌→✅ 触发链路：iframe 与 window.open 两条 scheme 通道实测不通（无面板、无 onNewWant 日志）；降级为请求文件通道后验证通过（点击 → IPC → 请求文件 → ArkTS ≤1s 消费）。
4. ✅ 面板与兜底：`requestPermissionOnSetting` 对本权限恒失败（**12100014**，真机实证），兜底跳应用信息设置页生效（settings 收到 `caller: ai.ohpc.zcode/EntryAbility, uri: application_info_entry`）。当前平台的实际体验＝跳设置页两步开启。
5. ✅ 运行中状态回流：**PC 上窗口覆盖/切回不触发 ability 的 onForeground/onBackground**（实证：从设置返回仅 WebAbility.onNewWant 日志）——已改为 1s 轮询 `checkAccessTokenSync`（值变化才写桥文件）。实证：应用运行中在系统设置开启权限，3s 内 `getOhosFullDiskAccessStatus()` 翻转为 granted:true，无需重启。
6. ✅ 设置页终态：已授权时「开启全盘文件权限」开关为开启且禁用，描述切换为「已开启。如需关闭，请到 系统设置 → 应用 → ZCode 中操作。」（截屏取证）。
7. 平台行为注意：系统设置中关闭 manual_settings 权限需应用不在运行（系统弹「禁止」确认框并强停应用）；atm 无法撤此类权限（`atm perm -c` 报 permission does not exist），测试撤权走设置 UI（深链 `application_info_entry` → 文件和文件夹）。


## 验收场景

- 全新安装首次进入主页面：右下角出现一次 toast；关闭后重装应用级别状态前不再出现；重启不再出现。
- toast 点「去开启」→ 出现系统「访问全盘文件」面板；开启后返回应用，设置页开关自动变为开启。
- 首次进入时已完成授权（老用户升级前已开）：不弹 toast。
- 登录页不弹（App 不挂载）；API Key 模式跳过登录进入主页要弹；退出登录再登录不重复弹（标记仍在）。
- 设置页开关在未授权时点击 → 同样拉起系统面板。
- 非 OHOS 平台：无 toast、无设置项、IPC 不产生。
