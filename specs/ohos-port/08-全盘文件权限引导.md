# 08 全盘文件权限引导（一次性 toast + 引导页）

`ACCESS_USER_FULL_DISK` 是 manual_settings 权限（对应系统设置「访问全盘文件」开关），`requestPermissionsFromUser` 对它不弹窗：应用只能检测状态并引导用户到系统面板开启。

## 平台事实

- 用户目录工具链 exec 的解锁来自 `CUSTOM_SANDBOX`（system_grant，装机即授）；**全盘权限不参与用户目录 ELF exec**。rc 文件、用户工具目录、`~/.ssh/config` 的读取由 `READ_WRITE_USER_FILE`（安装即授）覆盖。
- 全盘权限不守护核心功能：编辑器、agent、已授权工作区、用户 zsh 环境均不依赖它。它的作用是让终端/agent 访问 home 以外、且未经选择器授权的任意路径。
- 启动即索要属于过度索取；应用内提示只出现在引导页与主页 toast。

## 产品规则

1. 启动与窗口创建路径不出现任何全盘权限相关界面，也不调用权限请求 API。
2. **一次性 toast**：首次进入主页面（判定＝App 挂载；登录页 WelcomeScreen 期间 App 不挂载，天然排除）且未授权时，在右下角展示一次应用内 toast：说明用途 +「去开启」按钮。**不自动消失**——只有用户点关闭（×）才消失；「去开启」后 toast 保留（状态由轮询回流）。**不设登录态门槛**——API Key 模式跳过登录后无 user 对象也要展示。展示即持久化标记（renderer localStorage），之后启动/会话不再展示。「清除应用数据」后标记随 localStorage 重置。
3. **引导页说明**：职业引导向导（OccupationOnboarding，设置 → 引导 可重开）末尾的「鸿蒙系统环境介绍」一步（仅 OHOS）说明全盘权限用途/不开启的影响 + 当前授权状态 +「跳转」按钮（触发同一授权链路，状态经轮询回流刷新）。导航规则：偏好页「跳过」进入鸿蒙页，跳过语义（偏好按未选择记录）保留到鸿蒙页「开始使用」；鸿蒙页作为末页**不显示跳过按钮**，只有「开始使用」。
4. **状态回流**：用户从系统设置返回应用（`onForeground`）时 ArkTS 重查并改写状态，renderer 经推送自动刷新（授权成功不额外弹提示）。
5. 点击「去开启」不乐观翻转任何 UI 状态；以系统真实授权状态为唯一事实。

## 状态所有者与链路

```text
ArkTS EntryAbility（状态唯一采集者）
  │ onWindowStageCreate / onForeground：checkAccessToken(ACCESS_USER_FULL_DISK)
  │ 写桥文件 <haps/electron/files>/full-disk-access.json { granted, updatedAt }
  ▼
main desktopOhosFullDiskAccess.ts（桥文件读者 + fs.watch 推送）
  │ IPC：OhosFullDiskAccessStatus(invoke) / OhosFullDiskAccessChanged(send)
  │ env：ZCODE_OHOS_FULL_DISK_ACCESS="1"/"0" 快照（启动注入，watch 回调刷新；
  │      host/agent/Bash 经 spawn env 继承，让 agent 自知文件访问面）
  ▼
preload window.zcode → desktopPlatform（IPlatformService 可选方法）
  ▼
packages/ui：OhosFullDiskAccessPrompt（一次性 toast）+ OccupationOnboarding 引导步骤

授权触发（renderer → ArkTS，请求文件通道）：
  OhosFullDiskAccessRequest(send) → main 写 <haps/electron/files>/full-disk-access.request
  EntryAbility 前台 1s 轮询发现请求文件：删除 + requestPermissionOnSetting 拉系统面板
  （requestPermissionOnSetting 失败时 startAbility 跳应用信息设置页兜底）
```

- 桥文件路径约定与 window-theme 桥一致：main 侧写死 `/data/storage/el2/base/haps/electron/files`（ArkTS `this.context.filesDir` 的模块级形态，见 07 的目录说明）。
- 「已展示标记」归 renderer（localStorage key `zcode.ohos.fullDiskPromptShown`）；「授权状态」唯一事实是系统授权，桥文件是它的投影。
- 应用内不提供设置页开关；权限只能在系统设置中开启或关闭。

## 接口

- **iframe / window.open 导航自定义 scheme 在 OHOS Electron 上静默失败**（无 onNewWant、无外部协议分发），不能由 web 侧导航触发系统能力。触发统一走：renderer `OhosFullDiskAccessRequest` IPC → main 落 `full-disk-access.request` → EntryAbility 前台 1s 轮询消费并拉 `requestPermissionOnSetting`；失败兜底跳应用信息设置页。
- IPC（`packages/shared/src/channels.ts`）：
  - `OhosFullDiskAccessStatus`（invoke → OhosFullDiskAccessStatus）：main 读桥文件；文件不存在/损坏视为未授权（与系统真实状态的下一次 ArkTS 写入对齐）。
  - `OhosFullDiskAccessChanged`（main→renderer send）：桥文件 fs.watch 变更推送。
  - `OhosFullDiskAccessRequest`（send → void）：main 写请求文件。
- `IPlatformService`（均为可选，仅 Desktop-OHOS 实现）：`getOhosFullDiskAccessStatus()`、`onOhosFullDiskAccessChanged(handler)`、`requestOhosFullDiskAccess()`。
- agent 侧暴露：`ZCODE_OHOS_FULL_DISK_ACCESS`（`shared/runtimeEnv.ts` 常量
  `ZCODE_OHOS_FULL_DISK_ACCESS_ENV_KEY`）——main 启动时同步读桥文件注入，IPC watch 回调刷新
  `process.env`。**快照语义**：运行中的子进程不热更，授权变更以新会话生效（agent 提示词与
  `ohos-dev` skill 已教此语义与 `echo $HOME` 判定配方）。

## 平台行为

- 系统设置中关闭 manual_settings 权限需应用不在运行（系统弹「禁止」确认框并强停应用）。
- atm 无法撤此类权限（`atm perm -c` 报 permission does not exist）；撤权走设置 UI（深链 `application_info_entry` → 文件和文件夹）。
- PC 上窗口覆盖/切回不触发 ability 的 onForeground/onBackground；状态回流依赖 1s 轮询 `checkAccessTokenSync`（值变化才写桥文件）。

## 验收场景

- 全新安装首次进入主页面：右下角出现一次 toast；关闭后重启不再出现。
- toast 点「去开启」→ 出现系统「访问全盘文件」面板；开启后返回应用，状态自动刷新。
- 首次进入时已完成授权：不弹 toast。
- 登录页不弹（App 不挂载）；API Key 模式跳过登录进入主页要弹；退出登录再登录不重复弹（标记仍在）。
- 设置页不提供全盘权限开关；Desktop 权限不在本 spec 范围（由系统按访问弹窗，spec 18）。
- 非 OHOS 平台：无 toast、无设置项、IPC 不产生。
