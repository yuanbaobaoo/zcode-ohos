# 11 设备通道

HAP 内没有可用的 hdc server（沙箱禁 UDS bind），官方 `hdc` 一旦需要本地 server 就失效
（`hdc list targets` 空、exit 0）。设备通道因此统一走 **hdc-direct**：纯 JS、TCP 直连设备
`hdcd`（`127.0.0.1:<persist.hdc.port>`）。`ohos_hdc` 工具与 devecocli 都复用这条通道。

## 三个使用面

| 使用面 | 入口 | 说明 |
| --- | --- | --- |
| Agent 工具 | `ohos_hdc`（`core/src/capabilities/ohos-device/`） | 会话内直接 list/shell/file/install |
| Agent Bash | 应用内迷你 CLT（`<home>/.zcode/bridge/clt`） | host 启动注入 `DEVECO_CLI_CLT_PATH` / `COMMAND_LINE_TOOL_PATH`，devecocli 自动可用 |
| 运维逃生 | 同上 + `ohos_hdc shell` | 看屏幕用 `snapshot_display` + `file_recv`（非产品路径） |

## 为什么是 hdc-direct

- 官方 hdc = client + server：`hdc` 客户端必须先连本机 server（UDS），沙箱拒绝 bind → 起不来；
- `-s ip:port` 只是交给 server 的目标，绕不开 server；
- HAP 内的 ELF 受 hmac 白名单/代码签名管制（[03](./03-平台权限与系统约束.md)），不能塞原生 hdc；
- 纯 JS 库随 `glm/` 打包，agent 进程内 `import`，TCP 直连 hdcd——这是唯一可用路线。

## 组件与所有权

| 关注点 | 所有者 |
| --- | --- |
| 能力入口 / 开关 | `core/src/capabilities/ohos-device/`，`ZCODE_OHOS_HDC_BRIDGE`（`0/off/false/native/disabled` 关闭） |
| 工具 schema | `contracts/src/tools/ohos-hdc.ts`（zod 与 `toToolJsonSchema` 同源） |
| 依赖声明 / 资产获取 | `packages/desktop/package.json` 的 `hdc-direct` tgz；`bundled-hdc-direct-assets.mjs` 复制到 `glm/node-runtime/hdc-direct/` |
| 打包门禁 | `bundle-ohos.mjs` 预检：开关开且资产缺失直接失败 |
| 运行期调用 | `hdc-direct.ts` 动态 import，复用 `HdcSession` |
| devecocli 入口 | `packages/services/src/ohos/ohosHdcShim.ts`（迷你 CLT + hdc shim） |
| 环境注入 | `bootstrapOhosHostUserShellEnv()`：`DEVECO_CLI_CLT_PATH` / `COMMAND_LINE_TOOL_PATH` / PATH |
| 凭据与目标 | `~/.harmony/hdckey`（首次连接设备弹「允许调试」）、`~/.harmony/hdc-direct-targets.json` |

资产只读：运行期不下载、不改写。版本号只在 `packages/desktop/package.json` 一处人工输入，
lockfile integrity 校验。

## 数据流

```text
packages/desktop ──pnpm install──▶ node_modules/hdc-direct
      └─ prepare:agent-bundle ──▶ <glm>/node-runtime/hdc-direct/
            └─ HAP: resfile/resources/glm/...
                  ├─ ohos_hdc 工具（agent 进程内）
                  └─ <home>/.zcode/bridge/clt/sdk/default/openharmony/toolchains/hdc
                        └─ node <glm>/.../dist/src/cli.js "$@"
                              └─ HdcSession ──TCP──▶ hdcd 127.0.0.1:<port>
```

## 工具契约（`ohos_hdc`，仅 OHOS 注册）

| action | 语义 | 关键参数 |
| --- | --- | --- |
| `list_targets` | 列出可用目标 | — |
| `shell` | 在设备执行命令 | `command` |
| `file_send` | 上传文件 | `localPath`、`remotePath` |
| `file_recv` | 下载文件 | `remotePath`、`localPath` |
| `install` | 上传 HAP 并 `bm install -r -d`，可选拉起 | `hapPath`、`bundleName?`、`ability?` |

- 阶段控制动作 `screenshot` / `ui_input` / `dump_layout` 已随 dev 通道删除（[15](./15-平台适配治理与不变量.md)）；
  截图与 UI 交互由 Computer Use 承担。
- target 解析：`target` 参数 → `ZCODE_HDC_DIRECT_PORT` → `param get persist.hdc.port`。
- `bundleName`/`ability` 只接受 `A-Za-z0-9_.$`；上传文件名过滤为 `A-Za-z0-9._-`。
- 审批：`needsApproval: true`、`destructive: true`，与 Bash 同级；`list_targets` 同入口。

## devecocli 集成

devecocli **不读 PATH**，只按工具链根找 `sdk/default/openharmony/toolchains/hdc`；未显式指定时
回退到 HNP 的官方 hdc（同样起不了 server）。因此 host 启动时在应用 home 下生成**迷你 CLT**：

```
<home>/.zcode/bridge/clt/
├── version.txt                       # "# Version: 26.0.0"（CLT 有效性判据）
├── node/bin/node、tool/node/bin/node # 占位入口（exec PATH 的 node）
├── ohpm/bin/pm-cli.js、hvigor/bin/hvigorw.js
└── sdk/default/
    ├── sdk-pkg.json                  # {"apiVersion":26}
    └── openharmony/toolchains/
        ├── oh-uni-package.json
        └── hdc                       # sh → node hdc-direct cli.js "$@"
```

- 注入 `DEVECO_CLI_CLT_PATH` / `COMMAND_LINE_TOOL_PATH`（`??=`，用户显式值优先）并把
  toolchains 前置到 PATH；agent 的 Bash 继承。
- 占位入口是必须的：实测缺 node/ohpm/hvigor 时 devecocli 报
  `COMMAND_LINE_TOOL_PATH is invalid`（exit 1）。
- **能力边界**：设备侧命令（list/install/uninstall/start/stop/log/ui/screenshot）可用；
  `devecocli run` 等构建命令需要真实 CLT 的 node/ohpm/hvigor，不在迷你 CLT 承诺范围。
- 不修改用户安装的 CLT（A/B 已证明：官方 hdc + 环境变量仍 `No active devices`）。

真机验收：

```
$ devecocli device list
HUAWEI MateBook Pro  127.0.0.1:46273  device  2in1   (exit=0)
$ ohos_hdc shell "param get const.ohos.apiversion"  → 26
```

## 失败模式

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 「资产缺失」 | 打包未带 hdc-direct | 重新打包；`bundle-ohos` 硬失败拦截 |
| 入口文件缺失 | 依赖未安装/版本不含 `dist/src` | `pnpm install` 后重试 |
| tarball 校验失败 | Release 资产损坏 | `--frozen-lockfile` 会失败，换版本重发 |
| 首次连接卡住/被拒 | 设备未授权新公钥 | 设备上点「允许调试」 |
| `07880109 interrupted` | 私钥带口令 | 换无口令的 `~/.harmony/hdckey` |
| 连接超时 | 无线调试关闭/端口变化 | 重读 `persist.hdc.port` |
| devecocli `No active devices` | 没走迷你 CLT（env 未注入/被覆盖） | 检查 `COMMAND_LINE_TOOL_PATH`；重启应用让 host 重建 |

## 验收场景

1. OHOS 会话存在 `ohos_hdc`；`ZCODE_OHOS_HDC_BRIDGE=0` 时不注册、资产不打包。
2. `list_targets` 返回 `127.0.0.1:<port>`；`shell "id"` 返回 `uid=2000(shell)`。
3. 5 MB 文件上传后设备侧 md5 一致；`install` 已签名 HAP 输出成功并可拉起。
4. 资产缺失时返回结构化错误，不抛未捕获异常。
5. 全新 shell 里 `devecocli device list` 直接列出设备（无需手工 export）。
6. 系统提示词含「HarmonyOS Device Debugging」段，点明 hdc/devecocli 的平台事实与 `ohos_hdc` 路线。
