# 11 设备通道

设备调试走 **CLI**：Agent 在 Bash 里直接 `hdc` / `bm` / `aa`。`hdc` 由应用提供——
随包 `hdc-direct`（纯 JS，TCP 直连设备 `hdcd`），不依赖用户安装 CLT，也不要求本地
hdc server。应用内**没有** `ohos_hdc` 工具，也没有提示词工具段。

## 为什么由应用提供 `hdc`

- 官方 `hdc` 是 client/server：客户端先连本地 server，server 再转发到设备。沙箱起不了
  server，设备侧 hdc 又是 HiShell 裁剪版（`-m`/`-s` 均报 `Unsupport option`），所以
  官方客户端在应用内必然 `ConnectUds … status:-2`、`list targets` 空输出。
- 而 `$ZCODE_HDC_TARGET`（`127.0.0.1:<persist.hdc.port>`）就是设备端 `hdcd` 的 TCP
  端口，本身可达。`hdc-direct` 直连这个端口，因此 `list targets` / `shell` / `file` /
  `install` 在沙箱内可用。
- 取舍：`hdc-direct` 是协议实现，需要跟随 hdc 版本维护；但它是今天唯一能让「开发 →
  装机 → 调试」在应用内闭环的路径。官方 CLI 保留为**回退**：平台开放 hdc server 后，
  删掉随包资产即可回到官方实现。

## 使用面

| 使用面 | 入口 | 说明 |
| --- | --- | --- |
| Agent Bash | `hdc-direct`（应用提供） | `hdc-direct list targets` / `-t <target> shell …` / `file send\|recv` / `install` |
| 设备侧管理 | `hdc-direct shell "bm …"`、`hdc-direct shell "aa …"` | 安装、卸载、查询、启停都由设备侧命令完成 |
| 开发自测豁免 | `hdc-direct shell "uitest …"` / `snapshot_display` | 仅调试本工作区构建的应用（不变量 1 的豁免，见 [15](./15-平台适配治理与不变量.md)） |

## host 注入（唯一 owner：`packages/services/src/ohos/ohosUserShellEnv.ts`）

host 启动时对 `process.env` 做以下注入，agent 与其 Bash 子进程继承：

| 变量 | 值 | 缺失时 |
| --- | --- | --- |
| `ZCODE_HDC_TARGET` | `127.0.0.1:<persist.hdc.port>` | 不注入，Skill 让 Agent 自己 `param get persist.hdc.port` |
| `PATH` | 前置桥目录 `~/.zcode/bridge/bin`，其中的 `hdc` 是启动器 | 保持原 PATH |
| `DEVECO_CLI_CLT_PATH` | 用户已有的真实 CLT 根（`??=`，不覆盖） | 不注入 |
| `COMMAND_LINE_TOOL_PATH` | 缺省时从 `DEVECO_CLI_CLT_PATH` 补齐（devecocli 只认前者） | 不注入 |

- 端口来源：`param get persist.hdc.port`，host 启动时解析一次；失败不阻断启动。解析逻辑
  是纯函数 `resolveOhosHdcTarget`，由 `packages/services/test/ohosHdcTarget.test.ts` 钉住。
- **应用只提供 `hdc-direct`，不接管用户的 `hdc`**：桥目录生成 `hdc-direct` 启动器，
  内容是 `exec node $ZCODE_BUNDLED_RESOURCE_DIR/node-runtime/hdc-direct/dist/src/cli.js "$@"`。
  代码里没有任何 CLT 路径或安装布局假设。
- 用户自己的 `hdc`（HiShell PATH、`.zshrc`、CLT、brew、npm…）保持原样；Skill 说明它归
  用户所有，平台开放 hdc server 后可直接使用。
- 不在 PATH 里前置 toolchains：host 启动早于 home 可读时 `existsSync` 会失败
  （2026-11-20 真机：Agent 里裸 `hdc` 报 127）。

## 随包资产与打包

- 依赖：`packages/desktop/package.json` 的 `hdc-direct`（固定 tgz URL）。
- staging：`scripts/bundled-hdc-direct-assets.mjs`，由 `prepare-agent-node-bundle.mjs` 的
  `stageBundledHdcDirectRuntime()` 复制到 `bundled-agents/linux-arm64/glm/node-runtime/hdc-direct/`。
- 硬门禁：`bundle-ohos.mjs` 在 packaging 阶段校验入口存在，缺失时失败，不产出「能装但
  装不了应用」的 HAP。开关 `ZCODE_OHOS_HDC_BRIDGE=0` 时跳过（仅排障用）。

## 首次使用

`hdc-direct` 首次运行生成密钥 `~/.harmony/hdckey(.pub)`，设备弹一次「允许调试」对话框；
用户点允许后后续命令直接可用。密钥丢失/重装会再弹一次。

## 环境门禁（写进内置 Skill）

硬性要求只有两个：`node` 与 `hdc`。

```sh
command -v node || echo MISSING:node
command -v hdc  || echo MISSING:hdc
command -v devecocli || echo OPTIONAL-MISSING:devecocli
```

- 缺 `node`/`hdc`：停下、报告缺失项、让用户补；不猜绝对路径、不继续硬写工程。
- `devecocli` 是可选项：用户可用 node/npm 安装，或直接用 `hvigorw` 构建。
- `python`、`ohos sdk` 同样是用户自备、可来自任意来源。

## SDK 自动发现（skill 内三级降级）

1. **扫 `PATH`**：对每个 PATH 目录及其上 1–3 级检查 `sdk/default/openharmony`；
   并先看 `DEVECO_CLI_CLT_PATH` / `COMMAND_LINE_TOOL_PATH` / `DEVECO_SDK_HOME` 提示。
2. **按可执行文件反推**：取 `hdc` / `hvigorw` / `ohpm` 的 `realpath`，剥离
   `/sdk/default/openharmony/...` 后缀，或向上最多 6 级找 SDK 根。
3. **问用户**：把 SDK 路径要过来，用 `OHOS_SDK=<path>`（hvigor 另需
   `DEVECO_SDK_HOME=$OHOS_SDK/sdk`）重跑构建。绝不编造路径。

这条策略降低 CLT 的硬依赖：CLT、DevEco Studio、brew、npm、手工解包都只是"用户提供
SDK 的方式"，Skill 负责发现而不是要求某一种安装。

## 内置 Skill

`apps/zcode-cli/packages/bundled-skills/skills/ohos-dev/SKILL.md` 是设备调试的唯一提示词
来源，随包内置、`priority: 1_000_000`、system scope。覆盖：

1. 环境门禁与双端事实（沙箱内 create/build/sign/install 均可，依赖 tools 而非 CLT 绝对路径）。
2. TCP/目标写法：优先 `-t "$ZCODE_HDC_TARGET"`；`hdc tconn 127.0.0.1:$(param get persist.hdc.port)`。
3. `bm`/`aa` 配方：`hdc install -r <hap>`、`hdc shell "bm dump -n <bundle>"`、
   `hdc shell "aa start -a EntryAbility -b <bundle>"`、`force-stop`、`hilog`。
4. 失败模式：`hdc: not found`、键未授权、端口漂移的判定与处理。
5. 权限边界：`install`/`bm`/`aa force-stop` 属破坏性操作，先确认目标。

## 失败模式

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `hdc: not found` / 127 | 桥目录启动器未生成，且没有可回退的 CLT hdc | 检查 `~/.zcode/bridge/bin/hdc`；确认随包资产存在 |
| `hdc list targets` 空 | 未传 target 或设备端 hdcd 未监听 | `echo $ZCODE_HDC_TARGET`；`hdc -t "$ZCODE_HDC_TARGET" list targets` |
| 首次 `hdc` 弹「允许调试」 | 新密钥需要授权 | 让用户点允许；密钥在 `~/.harmony/hdckey` |
| `[Fail]` 连接超时 | 端口漂移或无线调试关闭 | 重新读 `persist.hdc.port`；`hdc tconn` 重连 |
| 安装成功但启动失败 | bundle/ability 写错或签名不符 | `bm dump -n <bundle>` 核对；`aa start` 看返回码 |
| devecocli 无设备 | 它内部仍调用官方 hdc（两段式） | 设备操作改用 `hdc`；devecocli 只用于构建/签名 |

## 验收场景

1. Agent 会话里 `hdc -t "$ZCODE_HDC_TARGET" list targets` 能列出设备。
2. `hdc install -r <hap>` 装机、`hdc shell "aa start …"` 拉起、`hdc shell "hilog …"` 看日志。
3. 缺 `node`/`devecocli` 时，Agent 停下报告缺失项，不写工程代码。
4. 随包 hdc-direct 缺失时打包失败，不产出半成品 HAP。
5. 关闭 `ZCODE_OHOS_HDC_BRIDGE` 时退回官方 hdc 回退链。
