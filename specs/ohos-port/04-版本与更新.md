# 04 版本与更新

鸿蒙版（OHOS runtime）不能自更新：应用经 HAP 分发，桌面端 electron-updater（AppImage/deb）在 OHOS 沙箱内既无 APPIMAGE 环境也无安装通道。更新策略为「**查询 + 引导外部下载**」：应用内查 GitHub 最新 release，发现新版本后弹窗展示更新日志，「前往下载」用浏览器打开发布页，用户手动下载 HAP 自行签名安装。

## 版本号规则

### Tag 语法（保持既有惯例，不做迁移）

```
v3.14.3                 上游基线同步
v3.14.3-ohos-fix2       移植早期修复
v3.14.3-ohos-patch7     移植补丁序列（常态发版）
```

不认识的 tag（如 `v3.14.3-dev`）按其 semver 基线参与排序（`shared/ohosReleaseVersion.ts` 的 `parseOhosReleaseVersion`）。

### 排序规则（`compareOhosReleaseVersions`）

1. 先比 semver 基线 `X.Y.Z`（标准 semver 大小）；
2. 基线相同比后缀等级：**base = dev(0) < fix(1) < patch(2)**；
3. 同等级比数字（数值比较，`fix10 > fix2`、`patch10 > patch7`，规避字典序错序）。

依据：本仓库发版时序为 `v3.14.3-dev` → `v3.14.3` → `fix2` → `patch1..N`，patch 是常态发版序列，排序与发布时序一致。

### HAP versionName / versionCode

- **versionName = 完整 tag 版本**（去 `v` 前缀，如 `3.14.3-ohos-patch7`），由 bundle-ohos.mjs 从 `app.template.json5` 生成 `AppScope/app.json5`（模板模式，同 `build-profile.template.json5` 先例；`app.json5` 不入库）。
- **versionCode = `(major*10000 + minor*100 + patch) * 1000 + seq`**，seq：base/dev=0、fix=N(1–499)、patch=500+N(501–999)。
  - 单调性验证：`3.14.3-ohos-patch7` = 31,403,507 < `3.14.4` = 31,404,000（跨基线恒增），int32 内（major ≤ 214）。
- 版本解析优先级（`build-metadata.mjs` 的 `ohosReleaseVersion`）：`GITHUB_REF_NAME`（CI tag 构建）> `git describe --tags --match 'v*' --exact-match`（本地恰在 tag 上）> `null`（开发态）。
- 开发态 `dev:ohos` 装机 versionName 用 git describe 结果或 `0.0.0-dev`。

### 客户端当前版本

main 进程运行时从 `out/metadata/build-meta.json` 的 `ohosReleaseVersion` 读取（`about.ts readBuildMetadata()` 既有模式），**不依赖 `app.getVersion()`**（OHOS Electron 移植层对该值的行为未验证）。值为 null（开发态）时更新检查禁用；调试可用 `ZCODE_OHOS_UPDATE_DEV_VERSION` 覆盖本地版本。

## 更新检查

| 项        | 值                                                                                                                            |
| --------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 数据源    | `GET https://api.github.com/repos/yuanbaobaooo/zcode-ohos/releases/latest`                                                    |
| 请求头    | `Accept: application/vnd.github+json` + `User-Agent`（GitHub API 必需）                                                       |
| 超时/上限 | 10s / 响应体 1MiB（对齐 forceUpdateGuard 模式）                                                                               |
| 节奏      | 启动即查 + 每小时轮询（复用 `AUTO_UPDATE_POLL_INTERVAL_MS`）                                                                  |
| 字段映射  | `tag_name`→版本、`body`→更新日志 markdown、`published_at`→发布日期、`html_url`→「前往下载」目标                               |
| 判定      | `compareOhosReleaseVersions(latestTag, 本地版本) > 0` 且未被用户跳过                                                          |
| 通道      | GitHub latest 仅返回最新正式 release（自动排除 draft/prerelease），单通道；跳过版本存 `skippedElectronUpdateVersions["ohos"]` |

### 状态与事件（所有者：desktop main `autoUpdater.ts`）

```
启动 → initAutoUpdater (production flavor)
 └─ OHOS 分支（替代 electron-updater 注册）
      ├─ 启动检查 + 每小时轮询，三级数据源依次降级：
      │    ① api.github.com /releases/latest（含更新日志）
      │    ② github.com /releases.atom（tag+日期，无日志正文）
      │    ③ gitcode.com 镜像 /info/refs?service=git-upload-pack（仅 tag 探测；
      │       git smart-http 纯协议无限流，镜像无 release 内容）
      │    所有源的跳转地址（htmlUrl）一律指向 GitHub release 页——镜像只做版本探测。
      │    ├─ 有新版且未跳过 → menuState = update-available
      │    │    { version, channel:"ohos", releaseNotes, externalDownload:true, downloadUrl }
      │    │    ├─ renderer 弹窗（复用 UpdateStatusDialog，仅 before-download 相位）
      │    │    │    「前往下载」→ IPC DownloadUpdate → main 应用内 BrowserWindow 加载 release 页
      │    │    │    「跳过此版本」→ IPC SkipUpdateVersion → settings["ohos"] = tag
      │    │    └─ 打开成功 → 广播 idle（弹窗收口，入口消失）
      │    ├─ 无新版 → idle；手动检查回 up-to-date
      │    └─ 三源全失败：轮询仅 warn 日志（静默）；手动检查回 UpdateCheckResult error
      └─ 永不进入 download-progress / update-downloaded / quitAndInstall（OHOS 无自更新）
```

互斥：复用现有 `checkForUpdatesInFlight` / generation 机制，轮询仅在 idle / update-available 态进入。

### 真机实证的平台事实（HAD-W32 / HarmonyOS 7）

1. **net.request 仅兼容单参 options 形式**：`net.request(url, {headers})` 双参形式会触发
   `TypeError: "listener" argument must be function`；必须 `net.request({url, headers, session})`。
2. **更新请求必须直连**：main 进程被 zshenv 重放注入代理环境变量后，Chromium net 栈经代理
   访问 api.github.com 被以 404 拒绝；用独立 partition 的 direct session（`setProxy({mode:"direct"})`）
   走 TUN 直连正常。
3. **api.github.com 匿名配额常态超限**：代理共享出口 IP 的 60 次/小时配额基本恒为 403
   `rate limit exceeded`，因此降级 `github.com/.../releases.atom`（网页端点无 API 限额，取首个
   entry 的 tag/时间，无更新日志正文；本仓库 CI 从不发 prerelease，首 entry 与 latest 语义一致）。
4. **GitHub 整站不可达时的镜像兜底**：GitCode 镜像（gitcode.com/yuanbaobaoo/zcode-ohos）只有
   tag 没有 release；其 Gitee 风格 API 匿名配额不可靠（429），tags 页面是 SPA 空壳，可靠的探测
   端点是 git smart-http 公告 `/.git/info/refs?service=git-upload-pack`（纯协议无限流，含全部
   refs/tags，注解 tag 的 `^{}` peeled 行需跳过）。镜像仅用于探查新版本——弹窗跳转、下载仍走
   GitHub。
5. **shell.openExternal 是静默假成功的空实现**：resolve 但不拉起任何浏览器（无进程/任务产生）。
   「前往下载」改为应用内 BrowserWindow 加载 release 页（Chromium 栈可达 GitHub）。

## 与桌面更新流的差异对照

| 能力                | Win/mac/Linux                        | OHOS                                             |
| ------------------- | ------------------------------------ | ------------------------------------------------ |
| 查询源              | zcode.z.ai manifest（YAML）          | GitHub latest API + atom 降级                    |
| stable/preview 通道 | 设置项 + API 参数                    | 无（单通道），设置项隐藏                         |
| 自动下载            | `autoDownloadAndInstallUpdates` 设置 | 不适用，设置项隐藏                               |
| 下载安装            | 应用内下载 → 重启安装                | 应用内窗口打开发布页，用户手动下载安装           |
| 强更 gate           | client/configs minimalVersion        | **跳过**（官方阈值指上游桌面版，对 OHOS 无意义） |

## 验收场景

1. **版本同步**：CI 打 tag 构建 → `hdc shell bm dump -n ai.ohpc.zcode` 的 versionName = tag 版本、versionCode 按公式递增。（已验证：v3.14.3-ohos-patch5 → 3.14.3-ohos-patch5 / 31403505）
2. **发现更新**：真机装旧 tag 版本 → 启动或手动「检查更新」→ 弹窗展示新版本号/日期 → 点「前往下载」应用内窗口打开 release 页 → 弹窗收口、更新入口消失。（已验证：patch5 检出 patch7 全链路）
3. **跳过版本**：弹窗「跳过此版本」后，后续轮询不再提示该版本；手动检查清除跳过记录后重新可见。
4. **已是最新**：装最新 tag → 手动检查提示已是最新。
5. **失败韧性**：断网时轮询静默（仅日志），手动检查弹错误提示，应用功能不受影响。
6. **设置隐藏**：OHOS 上设置 → 常规不出现「接受提前收到预览版更新」「自动下载并安装更新」；更新弹窗无「以后自动下载并安装更新」勾选框。
7. **dev 装机版本**：dev-ohos 全量装机 versionName=0.0.0-dev、versionCode=1e9（恒大于 release 编码，
   覆盖安装不受版本比较阻碍）；从 dev 版装回 release 包需先 uninstall（1e9 > release code，
   `install -r` 降级被系统拒绝）。
