# 24 开发包数据根与交付加固

> 状态：**数据根隔离已实施**（2026-11-25）；**交付加固项仍为方案**。

## 决策

- **正式包沿用 `~/.zcode`**，不变；**开发包使用 `~/.zcode-dev`**，沿用本仓库「开发身份加 `-dev` 后缀」的习惯（`bundleName` 用 `.dev`、label 用 `-dev`、数据根用 `.zcode-dev`）。
- 只隔离**数据根**，**不隔离真实 HOME**：zsh 登录环境、`~/.ssh`、`~/.gitconfig`、系统目录授权都依赖真实 home，改 HOME 等于让 dev 看到另一个用户。
- 加固项**下游适配层优先**，上游只做必需的 seam。

## 背景

- 凭据主密钥的资产库别名是 `ZCode Credential Encryption:sha256(凭据文件绝对路径)`（[16](./16-凭据安全存储.md) D2），而 OHOS 资产库条目**按应用（uid）隔离**。两个包共用 `~/.zcode` 时算出同一别名却各持不同条目：后启动的包要么查不到密钥触发自动重置（备份并清空共享凭据文件），要么用自己的密钥解对方密文失败 —— 登录态互相作废。
- 合法的 HAP 与 App Bundle 均约 522–525 MB，体积由 `libelectron.so`(187 MB) + app(225 MB) + glm(72 MB) 等必要负载决定；不存在"更小且可安装"的形态。缺 ACL 的 profile 会让 `hdc install` 报 9568289。

## 数据根隔离（已实施）

### 生效条件

`build-ohos --dev-identity`（即 `ohos:run` 的构建路径）在 resfile 组装副本里写 `config/dev-identity.json`；**main 与 host 各自读**同一个 `<app>/config/dev-identity.json` 并设置，读不到即正式包（行为不变）。host 必须自己读：OHOS 的 utilityProcess 由 appspawn 侧拉起，**不继承 main env**（spec 02），只靠 main 的 env 会让 host 仍落在 `~/.zcode`；agent 在 host 内以 worker 运行，继承 host env。正式打包（`ohos:bundle`）不带该步骤。

### 设置的变量

| 变量                    | dev 值                                                     | 说明                                           |
| ----------------------- | ---------------------------------------------------------- | ---------------------------------------------- |
| `ZCODE_DATA_ROOT_DIR`   | `<realHome>/.zcode-dev`（沙箱回退为 `<files>/.zcode-dev`） | 数据根，决定 `v2/`、日志、任务索引、凭据目录   |
| `ZCODE_HOME`            | 同数据根                                                   | CUA/终端/子进程按它找 dev 根                   |
| `ZCODE_SESSION_DB_PATH` | `<root>/cli/db/db.sqlite`                                  | Agent 会话库跟着 dev 根                        |
| `ZCODE_DATA_BASE_DIR`   | 不变（真实 home / 沙箱）                                   | base dir 同时影响 shell 环境等其它路径，不能改 |

目录授权迁回真实 home 后（`desktopOhosHomeGrant`）按同一规则重设，不会退回共享根。

### 上游 seam

- `packages/services/src/paths.ts`：`getZCodeDataRootDir()` 优先返回 `ZCODE_DATA_ROOT_DIR`，**只认绝对路径**；相对路径与空值回落 `{dataBaseDir}/.zcode`。
- `packages/desktop/src/main/desktopDataBaseDirBootstrap.ts`：`setting.json` 引导路径跟随数据根（`{root}/v2/setting.json`），否则正式包的自定义 `dataBaseDir` 会覆盖 dev 的隔离。

### 用户 shell 快照

`ZCODE_DATA_ROOT_DIR`、`ZCODE_SESSION_DB_PATH` 在 `SHELL_EXPORT_SKIP_KEYS` 中（`packages/services/src/ohos/ohosUserShellEnv.ts`）：用户 shell 快照合并不能覆盖引导设定的数据根。

### 凭据

`credentials.json`、`credential-source`、私有密钥文件与文件锁都在 `<root>/v2/`，随数据根整体隔离；两个包各自持有凭据文件与资产库条目，互不作废。

### 迁移

默认**不迁移**：dev 首次启动是空数据，正式包完全不受影响。旧 dev 数据留在 `~/.zcode`，不影响正式包读取。

### 不做

| 不做                                       | 原因                                                                          |
| ------------------------------------------ | ----------------------------------------------------------------------------- |
| 改 HOME 做隔离                             | zsh / ssh / git / 系统授权都依赖真实 home                                     |
| 改 vendor `web_engine` 注入 env            | 上游升级冲突大                                                                |
| 为体积裁剪 `libelectron` 或改 HAP 内部压缩 | 破坏签名与加载，且省不下多少                                                  |
| 把"不可用"自动当"损坏"清凭据               | 设备锁屏/钥匙串未解锁时会误删正常登录（`systemCredentialCipher.ts` 明确禁止） |
| 私钥/密码进 CI                             | 安全底线；CI 只出 unsigned                                                    |
| 把 `.app` 当可安装包分发                   | `hdc install` 直接 9568446                                                    |

## 未决项与残余风险

- 独立 CLI / Server / 远端 Host 不设置 `ZCODE_DATA_ROOT_DIR`，行为不变。
- 同一身份内的 `install -r` 升级若导致凭据文件路径或资产库条目变化，仍会出现 `CREDENTIAL_SECURE_STORAGE_UNAVAILABLE`，当前只能删凭据文件后重新登录；本期不提供 UI 恢复入口。
- 旧 dev 数据（`~/.zcode` 内的 dev 会话）不迁移；需要时手工复制到 `~/.zcode-dev`。
