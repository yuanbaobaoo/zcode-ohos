# 19 开发包身份

`pnpm ohos:run` 装机用的**开发包**与 `pnpm ohos:bundle` 打出的**正式包**必须有可区分的身份，并能在同一台设备上共存；正式包的身份、签名与产物名保持不变。

> 范围：本改造只隔离**包名与显示名（label）**。用户数据目录**不隔离**——两个包继续共用 `~/.zcode`（见「非目标」）。
>
> 开发包使用独立数据根 `~/.zcode-dev`，正式包保持 `~/.zcode`，见 [24-开发包数据根与交付加固](./24-开发包数据根与交付加固.md)。

## 背景

历史上 dev 装机与正式包共用 `bundleName`：开发装机靠「versionCode 1e9 > 正式版」覆盖安装，设备上同一时刻只有一套包，换方向安装还要先卸载。开发时无法同时对照正式版，安装也容易误覆盖。

现在开发包使用独立身份（`dev` product），与正式包并存，互不覆盖。

## 身份表（唯一事实源）

| 项                                  | 正式包                                 | 开发包（ohos:run）                             |
| ----------------------------------- | -------------------------------------- | ---------------------------------------------- |
| bundleName                          | `io.github.yuanbaobaoo.zcode`          | `io.github.yuanbaobaoo.zcode.dev`              |
| 设置页名称（app label）             | `$string:app_name` = `ZCode`           | `$string:app_name_dev` = `ZCode-dev`           |
| 桌面/启动器名称（ability label）    | `$string:EntryAbility_label` = `ZCode` | `$string:EntryAbility_label_dev` = `ZCode-dev` |
| 窗口/任务预览标题（页面 `<title>`） | `ZCode`                                | `ZCode-dev`                                    |
| 快捷方式 `wants.bundleName`         | 正式包名                               | `io.github.yuanbaobaoo.zcode.dev`              |
| 签名配置                            | `signingConfigs.default`               | `signingConfigs.dev`                           |
| product                             | `default`                              | `dev`                                          |
| 产物目录                            | `entry/build/default/outputs/default/` | `entry/build/dev/outputs/dev/`                 |
| 产物名                              | `electron-default-*.hap`               | `electron-dev-*.hap`                           |

规则：

| #   | 规则                                                                                                                                                                                                            |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **包名后缀只能用点号加一段**：HarmonyOS 的 bundleName schema 只允许字母、数字、下划线分段（`^[a-zA-Z](\w*[0-9a-zA-Z])?(\.[0-9a-zA-Z]\w*){2,}$`），连字符非法。所以包名是 `.dev`，用户看得见的 label 才用 `-dev` |
| 2   | 正式包身份只有一个来源：`AppScope/app.template.json5`（和 [15](./15-平台适配治理与不变量.md) 的不变量一致）。开发包身份从同一个模板**派生**成 `<release bundleName>.dev`，不另写包名字面量                      |
| 3   | label 资源成对存在，并且要同名同步：`app_name` / `app_name_dev`（AppScope，管设置页）与 `EntryAbility_label` / `EntryAbility_label_dev`（entry 模块，管桌面）                                                   |
| 4   | 两个包名都以 `io.github.yuanbaobaoo.` 开头、正式名是开发名的前缀，所以**不能用 `includes` 判断装没装**，设备探测必须按完整包名精确匹配                                                                          |
| 5   | 两个包共用用户数据目录 `~/.zcode`，不迁移也不改写路径                                                                                                                                                           |

## 构建侧：product + target

### 项目级 `build-profile.json5`（机器相关，模板入库）

- `app.products` 增 `dev`：`bundleName` = 派生的开发包名、`label` = `$string:app_name_dev`、`signingConfig` = `dev`（由 devecocli 回填）、SDK/`buildOption` 与 `default` 一致。
- `modules[electron].targets` 增 `dev`，`applyToProducts: ['dev']`；`default` target 只保留 `default`。一个 product 只能命中一个 target。
- 本机文件被 gitignore，早于本改造的 checkout 没有 `dev` 条目：`ohos:run` 在构建前把模板里的 `dev` product/target 合并进本机文件；同时纠正历史写法（`default` target 的 `applyToProducts` 里若含 `dev` 则移除）。合并只做「增量 + 该纠正」，不覆盖 devecocli 回填的 `signingConfig`。

### 模块级 `entry/build-profile.json5`（入库）

`dev` target 承载两处 per-product 覆盖：

| 覆盖项                                 | 值                                                     | 为什么                                                                                                                                                                 |
| -------------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source.abilities[EntryAbility].label` | `$string:EntryAbility_label_dev`                       | product 的 `label` 只管设置页名称，桌面图标名由 module 的 ability label 决定。少了这段，桌面还显示 `ZCode`                                                             |
| `resource.directories`                 | `["./src/main/resources_dev", "./src/main/resources"]` | 快捷方式 profile 里的 `wants.bundleName` 是写死的包名，hvigor 不替换，只能用 `resources_dev` 下同名的 `shortcuts_config.json` 覆盖。覆盖目录放前面，缺文件时回落主资源 |

### 签名

| 项                       | 做法                                                                                                                                                                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 只维护 dev 一套签名      | 材料在 `~/.ohos/config/dev_<工程目录名>_<hash>=.{cer,p12,p7b}`，由 devecocli 生成。正式 HAP 一律按未签名产出，签名由使用者自己处理，本仓库既不维护也不校验                                                                                                         |
| 生成签名前的包名临时改写 | `devecocli signature generate --product dev` 读的是 `AppScope/app.json5` 的 bundleName，不认 product 级覆盖。所以生成前把 `app.json5` 的 bundleName **临时**改成开发包名，结束后无条件还原；万一中断留下残局，下一次 `ensureOhosAppJson5` 会从模板重生成，自动修好 |
| 什么时候才调 devecocli   | 前置条件：devecocli 已登录、实名、有团队、至少一台设备（AGC 云设备或 hdc 连接）。`ohos:run` 只检查 `dev_*.p7b`，只有材料缺失、包名不符、profile 过期、已连接设备的 UDID 未覆盖时才去调，避免每次构建都跑网络。其它 product 的签名材料不参与判断                    |
| 强制重签                 | `--resign`（权限或 ACL 改过、profile 异常时用）                                                                                                                                                                                                                    |

### 构建流程（ohos:run）

```text
ensureDevSigning()        # 补齐 dev product/target（本机配置）+ 必要时 devecocli
                          #（临时改 app.json5 → 还原；写回 signingConfig dev）
build-ohos.mjs            # 与正式包同一套 resfile 组装
ensureOhosAppJson5()      # 从模板重生成 app.json5（versionName/versionCode + 还原 bundleName）
hvigorw assembleHap --mode module -p product=dev -p buildMode=debug
hdc install -r entry/build/dev/outputs/dev/electron-dev-signed.hap
aa force-stop / aa start -b io.github.yuanbaobaoo.zcode.dev
```

- dev 装机必须签名：未签名 HAP 装不上，脚本在 install 前就报可行动错误（登录/连接设备/`--resign`）。
- 正式包路径（`bundle-ohos.mjs`）**不做任何改动**：仍走 `product=default`、产出未签名 HAP（有本机 signingConfig 时 hvigor 照常签名，属用户本机行为）；本仓库只为 dev 包补齐 `dev` product/target。
- 窗口标题：桌面窗口标题跟随渲染页 `<title>`（Electron 默认行为），页面加载后会覆盖启动时的
  ability label，导致开发包的 dock/任务预览从 `ZCode-dev` 变回 `ZCode`。`ohos:run` 给
  `build-ohos.mjs` 传 `--dev-identity`，只把 HAP 内组装副本的 `out/renderer/index.html`
  标题改成 `ZCode-dev`（幂等，不碰本地 `out/`）；正式打包不传该开关，标题保持 `ZCode`。
- `--hqf` 增量：产物目录切到 `entry/build/dev`（target 段随 target 名变为 `dev`）；`bm quickfix` 无 `-b`，依赖 hqf 自身身份，所以安装判定必须先按开发包名确认已安装，否则回落全量。
- 基线文件按包名分文件（`build/zcode-dev-baseline-<bundle>.json`），开发/正式互不影响零变更早退。

## 验收

| Case        | 条件                                     | 期望                                                                                                                     |
| ----------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| OHOS-DEV-01 | `pnpm ohos:run`                          | 装出 `io.github.yuanbaobaoo.zcode.dev`；设置页与桌面名称均为 `ZCode-dev`                                                 |
| OHOS-DEV-02 | 设备上已有正式包，再跑 `ohos:run`        | 两个包同时在设备上，可分别打开；正式包不被覆盖或卸载                                                                     |
| OHOS-DEV-03 | 首启后查看包信息                         | `bm dump -n <dev bundle>` 的 `label` 为 `$string:app_name_dev`，`EntryAbility.label` 为 `$string:EntryAbility_label_dev` |
| OHOS-DEV-04 | 开发包「新建窗口」快捷方式               | 拉起开发包自身，不跳到正式包                                                                                             |
| OHOS-DEV-05 | `pnpm ohos:bundle`                       | 产物包名 `io.github.yuanbaobaoo.zcode`、label `ZCode`；`AppScope/app.json5` bundleName 为正式名                          |
| OHOS-DEV-06 | 旧 checkout（本机 build-profile 无 dev） | `ohos:run` 自动补齐后构建成功；不覆盖已有 signingConfig                                                                  |
| OHOS-DEV-07 | 生成 dev 签名被中断                      | 下次 dev/bundle 构建从模板重生成 app.json5，不残留开发包名                                                               |
| OHOS-DEV-08 | 未登录 devecocli / 无设备                | 给出可行动报错（登录/连接设备/`--resign`），不产出错身份包                                                               |
| OHOS-DEV-09 | 两包读写用户数据                         | dev 包使用 `~/.zcode-dev`，正式包保持 `~/.zcode`（[24](./24-开发包数据根与交付加固.md)）                                 |
| OHOS-DEV-10 | dev 包启动完成后悬停 dock / 看任务预览   | 标题保持 `ZCode-dev`，不回落成 `ZCode`                                                                                   |

## 非目标

- **数据目录已隔离**：开发包 `~/.zcode-dev`、正式包 `~/.zcode`，实现见 [24](./24-开发包数据根与交付加固.md)。
- 不为 Desktop 的源码开发/Preview 通道引入独立身份。
- 不改正式包的身份、签名与产物名，不做开发包↔正式包的数据迁移或同步。
